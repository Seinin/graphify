# 常数与网格

这一层不随红移重算，只把后面每一步都要用的两样基准钉死：温度基准与分辨率基准。微波背景温度被观测钉在黑体上，链上所有温度都相对它算——气体能冷却到多冷、自旋温度偏开光子温度多少，都得先知道当时的光子温度；盒子边长与网格数则决定每张场能分辨到多小的尺度，塌缩、电离与加热的空间图案有多精细，从这一步就已经定下，后面的块只能在这个分辨率上作画。

它在源码侧对应最底层的那几份公共文件：常数表把今天的微波背景温度、与 21 cm 跃迁对应的温度以及各类物理常数集中在一处声明，上面的块都从这同一处取用，不各自另写一份。成员只有一个——那个唯一不需要演化方程的温度。

## T_γ · CMB 温度

### 物理

厘米波背景是链上唯一温度被观测钉死的光：黑体谱、今天约 $2.7255\ \mathrm{K}$，整条链只把它当背景，不再改写。宇宙膨胀把光子波长一起拉长，黑体温度因此随红移因子线性升高，到宇宙黎明已是几十开尔文——这是链上唯一没有演化方程、只有缩放关系的温度。

公式就是一条缩放，前提是光子数守恒与自由膨胀：没有新的光子源注入，散射又足够弱，黑体形状得以保持；今天的温度由外部测量给出，它的精度直接决定吸收与发射分界落在哪个红移。

在自旋温度这本账里它当外源而非被算的量：气体靠散射与它交换能量，反向作用可以忽略——气体的能量密度远低于光子。它同时进气体的动力学温度与自旋温度里的光子项，没有参数简并、也不非局域；局限在它本身不含任何天体物理加热的痕迹，加热全部由气体与自旋两条线承担。

$$T_\gamma(z) = T_0\,(1+z),\qquad T_0 = 2.7255\ \mathrm{K}$$

### 代码解析

今天的微波背景温度在代码里只有一处来源：`Constants.c` 里的常数表（25–26 行），`PhysicalConstants` 结构中的 `T_cmb = 2.7255` 与 `T_21 = 0.0682` 并列——后者是 21 cm 跃迁对应的温度 $h\nu_{21}/k_B$，两个数放在一起，是因为自旋温度那套式子要反复比较「光子温度」与「跃迁温度」。

红移依赖不写在常数表里：`SpinTemperatureBox.c` 每次刷新快照时按当前红移重算一遍 `Trad = T_cmb * (1 + zp)`，并顺手存下它的倒数（1126–1127 行）。康普顿耦合项与自旋温度的表达式里要反复乘除这个温度，存下倒数只是省一次除法。看这段代码时要认准一点：它是**每快照一次、按红移重算**的标量，不是初始化时算一次就固定的常数——快照红移变了，它跟着变。

### 工程

- `src/py21cmfast/src/Constants.c:25-26`

```c
    .T_cmb = 2.7255,
    .T_21 = 0.0682,
```

- `src/py21cmfast/src/SpinTemperatureBox.c:1126-1127`

```c
    consts->Trad = physconst.T_cmb * (1.0 + zp);
    consts->Trad_inv = 1.0 / consts->Trad;
```

- 输入：常数表里的 $T_0=2.7255\ \mathrm{K}$ 与当前红移 $z$
- 产出：标量 $T_\gamma$：按快照红移刷新，供所有块取用

### 参数语境

本篇名下没有参数标签：$T_\gamma=T_0(1+z)$ 只由常数表里的 $T_0$ 与快照红移决定，天文参数与开关都碰不到它。它是"给定量"而不是可调量——CMB 温度是这条链的背景条件，亮温里的吸收项与自旋温度里的辐射温度都用它。
