# 常数与网格

这一层不随红移重算，只把后面每一步都要用的两样基准钉死：温度基准与分辨率基准。微波背景温度被观测钉在黑体上，链上所有温度都相对它算——气体能冷却到多冷、自旋温度偏开光子温度多少，都得先知道当时的光子温度；盒子边长与网格数则决定每张场能分辨到多小的尺度，塌缩、电离与加热的空间图案有多精细，从这一步就已经定下，后面的块只能在这个分辨率上作画。

它在源码侧对应最底层的那几份公共文件：常数表把今天的微波背景温度、与 21 cm 跃迁对应的温度以及各类物理常数集中在一处声明，上面的块都从这同一处取用，不各自另写一份。成员只有一个——那个唯一不需要演化方程的温度；网格那一半不是物理量，只是把高、低两套分辨率的尺寸做成一组宏。

这篇文档顺着这一层真实的样子写：先交代它在链上的位置与输入输出，再给出唯一那条物理关系（黑体温度的缩放），然后是它在代码里的两处落点——常数表与逐快照重算，接着是这一层的参数归属与陷阱，文末是成员卡片、代码地图与论文出处。

## 一、这块在链上做什么

**一句话**：给出全链共用的两个基准——光子温度随红移怎么走，以及空间网格有多细。

| | 内容 |
| :--- | :--- |
| 输入（链上） | 无。它是最底层的一层，不吃任何上游盒 |
| 输入（常数与选择） | 今天的微波背景温度 $T_0$（源码常量）；箱子边长与网格数（分辨率选择） |
| 输出 | $T_\gamma(z)$：按快照红移刷新的标量；以及一整套由网格数派生的尺寸与下标宏 |
| 下游 | 气体热与自旋温度一块取 $T_\gamma$ 作辐射温度；所有盒子都按这套网格尺寸分配与索引 |

**物理图像**：光子温度是这条链的背景条件，不是待解的量。它在每个红移上定下"宇宙当时有多热"；气体的动力学温度是向它靠还是离它远、自旋温度是被它拉回还是被 Ly-α 与碰撞拉走，都要先知道它。分辨率则是另一回事：它决定下面每一张场的最小尺度，塌缩在哪里成团、电离斑块有多大，从这个数就已经限死。

**为什么是独立一层**：$T_\gamma$ 没有一个"算出来"的时刻，它由测量给死；网格同样不含演化。两者都不属于任何一个过程块，却又是每个块都要用到的东西，所以单列为层——图上因此不可进入，进去也没有过程可讲。

## 二、物理骨架

光子数守恒，又没有新的光子源注入，黑体形状在膨胀中得以保持；温度随宇宙一起被拉低，反比于尺度因子，也就是正比于红移因子。这是本层唯一的一条关系：

$$T_\gamma(z) = T_0\,(1+z),\qquad T_0 = 2.7255\ \mathrm{K}$$

$T_0$ 由外部测量给出，它的精度直接决定吸收与发射的分界落在哪个红移。所以本层给出的是**给定量**：没有演化方程、没有求解步，也不含任何天体物理加热的痕迹——加热全由气体与自旋两条线承担。作为外源，气体与它交换能量时反向作用可以忽略（气体的能量密度远低于光子），因此它进下游的式子时是单向的。

网格那一半不是物理：它只回答"把盒子切成多少格"。平滑尺度、可分辨的最小尺度、以及派生格点数的换算全从它来，改它不改任何一条方程，只改同一套方程被采样的粗细。

## 三、代码：一张常数表与逐快照重算

### 3.1 常数表：`Constants.c`

全部物理常数集中在一个文件作用域的只读结构里（`Constants.c:4-43`），字段声明在 `Constants.h:18-63`。与温度有关的两个数并排放在一起：

```c
    .T_cmb = 2.7255,
    .T_21 = 0.0682,
```

（`Constants.c:25-26`。）`T_cmb` 是今天的微波背景温度，`T_21` 是 21 cm 跃迁对应的温度 $h\nu_{21}/k_B$——两者并列，是因为自旋温度那套式子要反复比较"光子温度"与"跃迁温度"（`:1144`、`:1250`）。文件头的注释写明：与原始 21cmFAST 不同的取值来自 Astropy 常数 v7.1.0，改过的行都留了 `was …` 的原值。整个结构声明为 `const`，运行期改不了。

红移依赖**不**在这里：常数表只有今天的值。

### 3.2 逐快照重算：`set_zp_consts`

真正把 $T_\gamma(z)$ 算出来的是自旋温度那一块的 `set_zp_consts`（`SpinTemperatureBox.c:1086`）。每次刷新快照时按当前红移重算一遍，并顺手存下它的倒数：

```c
    consts->Trad = physconst.T_cmb * (1.0 + zp);
    consts->Trad_inv = 1.0 / consts->Trad;
```

（`:1126-1127`。结构体注释写明存倒数只是为了省一次除法。）紧接着同一函数拿它派生出好几项预因子：Ly-α 耦合的预因子（`:1141`）、碰撞耦合的倒数（`:1144`）、康普顿项的 `Trad` 四次方（`:1147`）。所以在代码里，$T_\gamma$ 的样子是**一棵预因子树的根**，而不是孤零零一个数。

看这段要认准一点：它是**每快照一次、按红移重算**的标量，不是初始化时算一次就固定——快照红移变了，它跟着变。

### 3.3 网格那一半：`indexing.h`

分辨率不是一张场，而是一组宏：高分辨的盒子深、总格点数与 k 空间半数格点由 `DIM` 与 `NON_CUBIC_FACTOR` 推出，低分辨一套由 `HII_DIM` 推出（`indexing.h:42-73`），盒子体积与沿视线的长度也在同一处（`:32-37`）。这些宏没有"算一次"的时刻——它们是编译期展开的表达式，凡是需要盒子维度的地方都现取现算。

## 四、参数

本模块不携带参数标签：$T_\gamma=T_0(1+z)$ 只由常数表里的 $T_0$ 与快照红移决定，天文参数与开关都碰不到它。它是给定量而不是可调量——微波背景温度是这条链的背景条件，亮温里的吸收项与自旋温度里的辐射温度都用它。想换 $T_0$ 只能改源码常量。

网格那一半对应的是"数值与精度"一类的选择（`HII_DIM`、`BOX_LEN`、`NON_CUBIC_FACTOR`）：它们只改数据切多细与算起来多贵，不改物理——所有场都在新网格上重算一遍，图案的统计性质不变，能分辨的最小尺度跟着变。

## 五、陷阱

**一、这一层没有演化方程。** 在这里找"算 $T_\gamma$"的循环或求解步会一无所获：它是一条解析缩放，今天的值来自外部测量（§3.1）。

**二、红移依赖在下游重算。** 常数表只有今天的 $T_0$；要某个红移的光子温度，得自己乘 $(1+z)$，代码里这一步在 `set_zp_consts`（§3.2）。

**三、$T_\gamma$ 是一串预因子的根，不是一个孤立的数。** 改 $T_0$ 会同时改动 Ly-α 预因子、碰撞耦合倒数与康普顿项（`:1141`、`:1144`、`:1147`），于是自旋温度与气体温度一起变，不会只动一处。

**四、网格不是物理量。** 改 `HII_DIM`、`BOX_LEN` 只改分辨率与代价，不改算法：每一张场都要在新网格上重算一遍。把分辨率当物理参数去扫，得到的是同一模型的不同采样精度。

**五、常数表是只读的。** `physconst` 声明为 `const`，运行期改不动；换 $T_0$ 只能改源码重编译。

### 一份最小检查清单

- 要某个红移的光子温度：$T_0(1+z)$，别在常数表里找红移。
- 改了 $T_0$：预期 Ly-α 与碰撞耦合的预因子跟着变。
- 动分辨率参数：确认是在改采样精度，不是在改物理。
- 这一层只有 `T_γ` 一个成员，它名下没有参数标签。

## 六、T_γ · CMB 温度

它是本层唯一的成员，也是链上唯一温度被观测钉死的光：黑体谱、今天约 $2.7255\ \mathrm{K}$，整条链只把它当背景，不再改写（§二）。

代码上它分两处。今天的值在常数表里，与跃迁温度 $T_{21}$ 并列（`Constants.c:25-26`）；红移依赖在自旋温度那一块的 `set_zp_consts` 里按快照重算，并存下倒数（`SpinTemperatureBox.c:1126-1127`），随即派生出 Ly-α、碰撞耦合与康普顿几项预因子（`:1141`、`:1144`、`:1147`）。

**它的位置是背景条件。** 气体冷却到多冷、自旋温度偏开光子温度多少，都要拿它比较；局限在它本身不含任何天体物理加热的痕迹——加热全部由气体与自旋两条线承担，它只提供那个被比较的基准。

论文出处：§3.2 全局信号的演化（`docs/论文/Pritchard & Loeb 2012 Review.pdf`）。
