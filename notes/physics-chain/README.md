# 物理链（「物理视角」页）的规则与口径

这份文件是**口径的账本**：本页的规矩都记在这里，改代码/改真源之前先读它。数据在 `chain.json`（真源，逐字转录自 PDF）、代码论文清单与等式对照在 `papers.md`、一模块一篇的模块文档（共 11 篇）在 `modules/`。

## 一、划分依据：与代码同构（一个 `.c` + 一个 `Compute*` + 一个输出的盒子 = 一个块）

一级画的是**代码里的模块边界**：`CosmoTables`（`cosmology.c`）、`InitialConditions`（`InitialConditions.c`）、`PerturbedField`（`PerturbedField.c`）、`HaloCatalog`（`HaloCatalog.c`）、`PerturbedHaloCatalog`（`PerturbedHaloCatalog.c`）、`HaloBox`（`HaloBox.c`）、`XraySourceBox`（`SpinTemperatureBox.c`）、`TsBox`（`SpinTemperatureBox.c`）、`IonizedBox`（`IonisationBox.c`）、`BrightnessTemp`（`BrightnessTemperatureBox.c`）各是一个**过程块**；另有 1 个**层**：常数与网格（`Constants.c` / `Constants.h`）。块的 `codeAnchor` 就写着这三件套：**文件 · `Compute*` 函数 · 输出的盒子**。

- **块名用物理语言，代码坐标只活在数据里**：一级上不出现文件路径、函数名与阶段号；文件 / 函数 / 盒子名只在产物 `codeAnchor` 与本账本 §七 的表里，属性页不印它们（口径见 §五、§九 第 7 条）。
- **块内 = 这个模块算了哪些量**：成员取自该模块输出盒子的字段（`ts`、`jalpha`、`eps_heat`…）。可进入的块 MUST 至少 2 个物理量成员、MUST 至少一条**块内关系**（两端都是本块成员的数据边，带 `codeRef`）；做不到就并入相邻块，MUST NOT 留一个点不进、进去只有一个框的空入口。`kind: layer` 的层 MUST NOT 可进入。
- **成员之下不再有图上的东西**（实现步骤 `step:*` 已退场）：步骤不上图，成员因此没有「进入」这一层——怎么算的写进**模块文档里那个成员那一节**（`### 工程` 里逐步骤成 `####` 小节，小节标题 = 真源核定的函数名，每条落点带一句说明，末尾给 `输入：` / `产出：`）。判据：**图上最细的对象是成员**（层的成员也是物理量），再往下都是"怎么算"，归文档。
- **一级的边只有块与块之间的接口**：21 条接口边 + 2 条跨红移回流边。成员怎么加减都 MUST NOT 动它们（自检按展开前的清单逐条比对端点与条数）。
- **"未在代码里定位到"这句话有门槛**（判据）：只许在**搜够了**之后写。判据：① 全仓搜（不只一个文件）；② 换同义词与相关量名（`x_c` 要找 `xc_inverse`、`1/x_c`、`kappa_10` 这类）；③ **写明搜过什么**（在哪个文件、试过哪些名字）。**"我没找到"≠"代码里没有"**——先如实写"我搜了 X、Y、Z 没命中"，再往下查，别把没搜到写成没有。
  - 反例：`x_c` 曾写成「未在代码里定位到」，实际就在 `SpinTemperatureBox.c:1074`（叫 `xc_inverse`）——只是当时只搜了一个文件、只试了四个名字。
  - **真正"代码里没有"的**才写"**代码不产出**"，而且要有正面证据（例如 `P_21`：产物清单 P01–P17 里没有功率谱，核心只输出盒子与光锥）。
- **理论推导与代码实现"完全两码事"的量：图上按代码画，理论写进文档**。判据：某个量的理论式（PDF 里那个式子）与代码实际执行的算法**不是同一套**——不是"一行 vs 一串"的粒度差，而是**算法本身就不同**。这时：**图上以代码为准**（节点与边照代码的实际步骤画），**理论在文档里给**（记明对应 PDF 的哪一节 / 哪一 Eq，并注明"代码用的是另一套算法"）。
  - 已确认属于这一类（自查，2026-09-29）：`Q_HII / x_HI`（理论是 Eq.3 的一阶 ODE；代码是游程集 / 逐格点判据，**不求那个 ODE**）、`T_S`（理论是 Eq.5 的三个温度调和平均；代码是沿视线分**径向环**积分）、`φ(M_1500)`（理论是 Eq.12–Eq.14 的 Schechter 形式；代码把晕质量函数换元到绝对星等轴，**不拟合 Schechter**，式中的 φ*、M*、α 在代码里没有对应物）。
- **同一套算法、代码比论文式子多几项：摘要给代码的完整表达式**。判据：代码执行的就是那个量的算法，只是带上论文省略的修正项——这不是「两码事」，但摘要同样不能给论文的简式；论文的简式记进真源 `theory`，并注明它是哪一 Eq 的特例。
  - 已确认属于这一类：`f*`（Eq.1 的幂律与低质端指数截断之外，代码还有高质端换指数的双幂律、每个晕的对数正态散射、硬截断到 1）。
- **一级上并存"量 / 谱 / 函数 / 过程"，用颜色区分种类**：**物理量**（`T_S`、`x_HI`、`M_min`）、**谱**（`P_21`、物质功率谱 `P(k)`）、**函数 / 关系**（晕质量函数 `dn/dM`、光度函数 `φ(M_1500)`、标度关系）都在同一级——它们不是同一类，但**用颜色区别种类**就够了，不因此分层、不因此另开页面。**观测量**（根）单独一色，**块内**节点用暗色。
  - 连带结论（回答"功率谱、质量函数要不要立一级节点"）：**要**。它们是物理层的"谱 / 函数"，各自可以有内部结构（`dn/dM` 的成员里是 `HMF` 用哪种、`P(k)` 的成员里是 `POWER_SPECTRUM` 用哪种）。
- **块内只放物理，工程进步骤**：块里出现的实现动作（网格装配、缓存、并行、断点续算）一律挂到某个成员的**步骤**下（默认收起），MUST NOT 平铺在同一层。层次判据：**这一项是不是一个物理过程 / 物理量 / 物理参数？** 是 → 块或成员；不是 → 步骤。
  - **附带结论**：物理页面里**不设"工程与装配"这类收起的区块**——那等于把工程搬进这张图。工程的地盘是画布页；需要时用「看实现」这类出口跳过去，而不是在本层里塞一个工程区。
- **虚线框只剩一个用途**：这个流程/模块在某些配置下**根本不存在**（并写明由哪个参数决定）——见 §八 第 7 条末。表面上现在一处都不画（查证结论见 §八）。
- **参数与这条链的接缝**：
  - **驱动量**挂在公式流的两端（决定"算什么"）：`f*、ζ、T_vir^min、L_X` 四个。
  - **效应开关**（`USE_*`、`PHOTON_CONS_TYPE`…）挂在**边**上——画成**虚线箭头 + 箭头上的虚线框**（沿用仓库"虚线 = 条件/可选"的既有语义），数据里是 `gatesEdges`。
  - **实现选择**（`INTEGRATION_METHOD_*`、`HMF`、`POWER_SPECTRUM`、`SOURCE_MODEL`…）挂在**块**上（数据里是块的 `tags`），标明"可选的实现"。
  - **数值与精度**（`R_MAX_TS`、`N_STEP_TS`…）**暂不纳入**。
  - 这三类的判据以 **§八 第 7 条**为准（2026-09-29 校正：这一段原先把三类混写成"数值参数 + 效应开关"，并按代码类分流，已改按逻辑分流）。

## 二、块 / 成员 / 步骤：三级怎么分（判据不看代码体量）

1. **块** = 代码里的一处封装：一个 `.c` 的 `Compute*`，产出一个盒子。换掉它改变的是"这个环节走哪条路"（`SOURCE_MODEL`、`HMF`、`POWER_SPECTRUM`）。
2. **成员** = 这个模块输出盒子里的一个物理量 / 谱 / 函数：它是独立成立的量（随红移成立的函数或场），不是某一步的中间缓冲。
3. **步骤** = 某个成员怎么算出来的一步（滤波器、积分器、条件表、离散累加）：只服务一个成员、只在代码里存在，MUST NOT 单独成块。
4. **判据不看代码体量**：
   - **反例提醒（最容易搞错的地方）**：`mmin` 在代码里只有一行幂律、很小，但它是 Eq.2 的独立物理量 → **成员**；`HaloBox.c` 是个大文件，物理上只是"把 Eq.1 / Eq.4 的积分铺成网格" → 它是**块**，内部的离散累加、滤波、网格装配是它成员下面的**步骤**。
   - **拿不准时的兜底**：问一句"科学家会单独问『这一步是什么』吗？"——会 → 块或成员；不会（"累加到网格怎么做"）→ 步骤。

## 三、防漏的硬规矩（自检来守）

- 每个公式量/边 **必须有至少一条"算法锚点"**（求值方式 / 所处循环层级（初始化一次·每红移一次·红移循环内子步） / 受哪些离散化参数控制 / 代码落点），**或者显式标注「未在代码里定位到」**——不许静默留空。
- 效应开关门控的箭头必须真实存在（否则那条虚线无处可挂）。
- 公式 MUST 逐字等于真源；生成器不许改写。

## 四、不做（边界）

- **不做评估层**：不加批注/评估字段（评估是使用者自己的事）。
- **不凭印象补文献或参数含义**：来源论文只在代码注释里真实写着时才填；缺就留空，并在自检日志里报数量。
- **算法流里的纯工程细节不进这一页**（缓存、持久化、并行、断点续算、HDF5 落盘 → 属画布 S02/S03/S16 的管辖）。
- **不加单位/量纲**：图上只给符号、公式与出处，不做量纲标注。

## 五、命名政策

- 图上**物理量按 P&L 2012 的写法**显示（`f*`、`ζ`、`T_vir^min`、`x_HI`、`T_K`、`T_S`、`δT_b`、`P_21`、`τ_e`）；**不追代码变量名**。
- 同一个量的不同名字，以 P&L 的写法为准；代码名只作附注字段（自检断言：节点符号不许是代码常量名）。
- **名字里不带代码坐标**：框上的块名与成员名、步骤名、模块文档的文件名与标题（`#`–`###`）都只写名字（`气体热与自旋温度`、`解自旋温度`、`thermal.md`）。阶段号与模块码（`S14.3.1`、`M8`）是**代码坐标**，只活在数据里（`stage` / `stages` / `stepId` / 源码引用的 `label` / `codeHints`）与检索命中面上——按 `S14` 检索照旧能查到，但界面上一个都不印（自检的「呈现面」一节守这一条：标签 / 落点 / 散文 / 模块文档 / 命中说明五类出口都在生成物与真源上重算）。

2. **层只有一个**：常数与网格（`Constants.c`）。它的成员 `tgamma` 是**物理量**、计入 38，代码锚是文件级（`codeAnchor.kind === 'files'`）；层的代码引用由真源按整文件区间直接给出，不靠汇总（§九 第 4 条）。**文件不挂成员**：层的锚里那些文件名不是"成员"，它们只在 `codeAnchor` 里出现，所以模块文档没有文件成员那一种。
3. **进到块里能看见什么**：块内 = 成员 + 块内关系 + 对外输入（灰显的上下文，不计入成员数）。**成员不再展开**——步骤不上图，只在文档里（`modules/<块>.md` 里那个成员节的 `### 工程`，逐步骤 `####` 小节），所以「进入」这个入口只在过程块上出现（层与成员都没有）。块的成员由真源 `blocks.items[].members` 唯一决定，视图不自己推导。
4. **开关挂在哪条边上**：效应开关写进 `gatesEdges`，指向它门控的那条边（`USE_X_RAY_HEATING → ε_heat→T_K`、`USE_MINI_HALOS → ρ̇*→Ṅ_ion`…）。
5. **落点都核到核心行**：47 条成员落点与 31 个计算单元的步骤落点逐条给出文件 + 行区间，产物 `stats.pendingUnits` 为空。核不到核心行的单元 MUST NOT 拿整文件或别的函数顶替——它们如实进这份清单，构建与自检都会报出来（见 §三）。

**落点精度**：`codeHints` 支持**阶段级**与**子过程级**键，生成器把每个落点同时挂在两套键下，所以「看实现」落在对的那几个函数上，而不是该阶段的前几个（`build-physics-chain.mjs`）。

## 八、参数分流：宇宙学挂标签，天体物理进抽屉

1. **宇宙学与物质背景的参数分两类处理**：
   - **控制性**（决定走哪条路的选项）：**作为标签挂在模块上**（被挂的模块**不**画虚线框——虚线框 = 整段流程非必要，与"参数可选"不是一回事，见第 7 条）。已核实归属：这类选项在 `MatterOptions`（`wrapper/inputs.py:560`）——`HMF`、`POWER_SPECTRUM`、`PERTURB_ALGORITHM`、`SOURCE_MODEL`、`SAMPLE_METHOD`、`FILTER` / `HALO_FILTER`、`FDM`、`HMF_FINDEX`、`USE_RELATIVE_VELOCITIES`、`USE_INTERPOLATION_TABLES`、`KEEP_3D_VELOCITIES` 等，**不在** `CosmoParams` 里。
   - **硬编码常量**（源码里写死的数，如 `Constants.c:25` 的 `T_cmb = 2.7255`）：**只写进文档，不上图**——不替这类常量建节点，也不去关心它们。
2. **天体物理参数是最重要的一层**：要能**当词条检索到它作用的流程**。它与宇宙学参数**分开处理**，单独做一个「天体物理参数」抽屉：选中某个参数词条 → **高亮它相关的模块**（不另开页面）。
3. 因此参数在数据里是**两条通道**，视图上也是**两套入口**：宇宙学（标签 + 虚线框）与天体物理（抽屉 + 高亮）。
4. **开关写箭头上**：`AstroOptions` 的开关（`USE_*`、`INTEGRATION_METHOD_*`、`PHOTON_CONS_TYPE` 等）继续画在它门控的那条**边**上（虚线箭头 + 箭头上的虚线框），**不**改成挂模块的标签——它描述的是"这条依赖要不要走"，不是"这个模块存不存在"。
5. **参数按"在物理里起什么作用"分流，不按"是不是用户输入"分流**（⚠️ **下表按"代码类"划的两行——"宇宙学控制性选项"与"天体物理开关"——已按第 7 条作废**，）：

| 类别 | 例子（带归属类） | 处理 |
| --- | --- | --- |
| 天体物理数值参数 | `F_STAR10`、`F_ESC10`、`M_TURN`、`L_X_MINI`、`A_LW`…（`AstroParams`，58 个） | 抽屉词条，可检索，选中高亮相关模块 |
| 天体物理开关 | `USE_MINI_HALOS`、`USE_TS_FLUCT`、`INTEGRATION_METHOD_*`（`AstroOptions`，17 个） | 写箭头上（见第 4 条） |
| 宇宙学控制性选项 | `HMF`、`POWER_SPECTRUM`、`SOURCE_MODEL`、`PERTURB_ALGORITHM`…（`MatterOptions`） | 挂模块标签，被挂模块画虚线框 |
| 宇宙学数值参数 | `hlittle`、`OMm`、`OMb`、`POWER_INDEX`、`Y_He`…（`CosmoParams`，11 个） | **当常量处理：只写出来（列进数据/文档）即可，不上图、不深挖**。不替它们建节点、不追它们进哪条公式 |
| 数值与精度参数 | `R_MAX_TS`、`N_STEP_TS`、`PHOTONCONS_CALIBRATION_END`（现有 `numeric` 组）＋ `HII_DIM`、`BOX_LEN`、`N_THREADS`、采样器参数（`SimulationOptions`，待逐条核实） | 归「数值与精度」一组：可检索，并标明"只改离散化与代价、不改物理" |
| 硬编码常量 | `Constants.c` 的 `T_cmb = 2.7255` 等 | 只写文档，不上图 |
| 代码内部派生量 | `_BOX_LEN`、`_DIM`、`_SIGMA_8` ↔ `A_s`、`_base_cosmo` | 不列成条目；在相关词条里注明"由…推得" |

6. **"用户参数"不是一类物理角色**：用户能设的（模板 / YAML / 代码默认）与代码里那四个结构体是**同一批参数**；"从哪来、能不能被覆盖"作为**词条上的来源字段**记录，不上图。
8. **两处收口**：
   - **分析侧自选的采样波数不进图**：功率谱曲线上取哪个 $k$ 是分析时的选择，不是模型参数（代码里没有对应的输入量），链上因此不含这个对象——既不上图，也不进参数表。
   - **论文索引只挂"拟合公式 / 经验模型"那一类**（代码注释里真实引用的那些：标度关系、晕质量函数、逃逸分数、X 射线谱、滤波、传输函数…）；**经典理论过程不配论文**（21 cm 基本物理、复合、康普顿耦合、碰撞耦合属教科书内容，不需要多加考虑）。⇒ "缺口 4：过程 ↔ 论文映射"这一设想**作废**，不另建映射。

7. **按代码类分流是错的，改按逻辑分流**（2026-09-29 校正）：
   - `MatterOptions`（宇宙学/物质侧）与 `AstroOptions`（天体物理侧）的分界是**按配置对象**，**不是按逻辑**——两边都有"效应开关 / 实现选择 / 数值开关"三类：`USE_RELATIVE_VELOCITIES`、`FDM` 是宇宙学侧的**效应开关**；`INTEGRATION_METHOD_*`、`HMF`、`POWER_SPECTRUM`、`SOURCE_MODEL` 是天体物理/物质侧的**实现选择**，不是开关。所以第 5 节表里"宇宙学控制性选项"与"天体物理开关"两行**按类划的写法作废**，按下面这张表划：
   - **逻辑上只有三类**（据此决定画在哪）：

   | 逻辑类别 | 判据 | 例子 | 画在哪 |
   | --- | --- | --- | --- |
   | 效应开关 | 加/减一条**物理项或依赖** | `USE_X_RAY_HEATING`、`USE_MINI_HALOS`、`USE_TS_FLUCT`、`USE_RELATIVE_VELOCITIES`、`FDM` | **箭头上**（虚线箭头 + 箭头上的虚线框） |
   | 实现选择 | 在几种公式/算法里**选一个**，模块本身总在 | `HMF`、`POWER_SPECTRUM`、`SOURCE_MODEL`、`INTEGRATION_METHOD_*` | 挂**模块**标签，写明"可选的实现"；模块**不**画虚线框 |
   | 数值/性能开关 | 不改物理，只改精度与代价 | `MINIMIZE_MEMORY`、`USE_FFTW_WISDOM`、`N_THREADS` | **暂不纳入** |

   - **虚线框的语义**：虚线框 = **这个模块/流程是非必要的**（有些配置下根本不存在），**不是**"这个参数可选"。因此只用在**某个选择会让整段流程消失**的地方——按现有读点最像的是 `PHOTON_CONS_TYPE = no-photoncons` 时那条光子守恒校准流程不参与（`IonisationBox.c:1373`、`scaling_relations.c:70-127`），**待用代码确认后再画**。
   - **每条虚线框必须写明"由哪个参数决定它在不在"**：只画虚框不写原因，读者只会困惑。
   - **虚线框的落点查证（结论：表面上现在一处都不画）**：原以为 `PHOTON_CONS_TYPE` 会让整段光子守恒校准消失，查代码后**不成立**——
     · `set_scaling_constants(..., bool use_photoncons)`（`scaling_relations.c:36`）的第三个参数是**调用点写死的**：`HaloBox.c:604,677,796` 与 `IonisationBox.c:142` 传 `true`，`SpinTemperatureBox.c:933,1580` 传 `false`，所以它**不等于** `PHOTON_CONS_TYPE != 0`；
     · 真正的开关在函数体内：`PHOTON_CONS_TYPE == 2 / == 3`（`scaling_relations.c:70,72,125,127`）与 `== 1`（`IonisationBox.c:1373`）——`no-photoncons`（默认）时跳过的只是**一处修正**，不是一个模块、也不是一段流程。
     ⇒ 按"虚线框＝整段流程非必要"的语义，**表面不该画虚框**（画了就是过度声称）；那处修正是实现细节，按"步骤不上图"的口径，它的落点写在模块文档里那个成员的步骤小节里，也不用虚框标。
   - **画布已支持该样式**：`node.conditional` / `edge.conditional` → `conditional` 类（`cytoscapeSetup.ts:678,727`）。真要画时只给数据加一个字段，不必改渲染。

## 九、引用口径：叶子最细、祖先 = 并集、模块 = 成员的并集

**一句话**：每个对象的引用由**最深一层的落点**唯一决定，上级**不自造**引用。

1. **图上最细的对象是成员，最细的落点是步骤**：18 个实现步骤（`step:*`）不再上图，但它们的落点照旧按计算单元核定，然后**并进所属成员**——代码引用进那个成员的「源码」（生成器按单元收的那几条，只带 `文件:行`、不另给笔记引用），怎么算的写在模块文档里那个成员那一节的 `### 工程`（逐步骤 `####` 小节，标题 = 核定函数名）。成员自己那几条核心行与这些步骤落点一起去重排序，逐条可对拍。
2. **祖先 = 自身的 ∪ 全部直接子节点的**：`refs(节点) = 去重排序(自身的 refs ∪ ⋃ 直接子节点的 refs)`（子节点按 `parent` 反向表算）。
3. **模块 = 成员的并集**：`refs(块) = 去重排序(块自身那几条 ∪ ⋃ 成员的 refs)`。块**不看 `parent`**，成员只认真源 `blocks.items[].members`（归属的唯一来源）。
4. **层的代码引用直接给出，不靠汇总**：层的成员是常数，真源里本就没有它的 `codeHints`，汇总一定是空的——那条**文件级**代码落点（`codeAnchor.kind === 'files'`，行区间 = 1 到文件末尾）与 1 条笔记引用写在真源里，生成器照抄。
5. **去重键与排序**（生成器与自检**各实现一遍**再逐条对拍）：

   | 类别 | 去重键 | 排序 |
   | --- | --- | --- |
   | 代码引用 | `file:line:endLine` | 文件路径 → 行号 → 结束行，**逐字符**比较 |
   | 笔记引用 | `docId#anchor` | 文档路径 → 锚点，**逐字符**比较 |

   去重键**不含 `label`**（同一条落点会同时挂在父与子、两边标签不同，带上就永远去不掉重）；排序**不用 `localeCompare`**（它会随运行环境的 ICU 变，产物会抖）。代码引用整体排在笔记引用前面。
6. **视图只读、不自己汇总**：物理链页读生成物给的 `refs`；`Inspector` 的两个入口按 `file` 是否为空把它分成「看实现」与「看文献」，数量标号 = 对应清单的长度。自检从叶子**独立重算**一遍再逐条对拍，多一条、少一条都失败并指名对象与那一条。
7. **反面**：块属性页**不再**出现「代码锚」「阶段号」这类点不开的摘要（字段仍在生成物里、自检仍逐条断言；"这块 / 这个量算在哪段代码里"由「看实现」的落点回答）。

### 模块文档（位置与形状）

- **性质**：这 11 篇是**手写的 md**，站点按 `docId` 直接读盘渲染，生成器不产它们（`Graphify/scripts/build-physics-chain.mjs` 只算引用入口：`docId` 与锚点）。改正文 = 直接改 md；这批文件的正文不与真源重算对拍，「位置 / 标题 / 锚点」另有门禁（见下）。
- **位置**：`docs/notes/physics-chain/modules/`，共 **11 篇** —— 一个块一篇（`modules/<块>.md`），成员不单独占文件、在块那一篇里各占一节。**文件名＝块名**（块的 id 去 `block:` 前缀，如 `block:thermal` → `thermal.md`），标题＝块名，不带模块码。
- **一篇的形状**：`#` 块标签 + 一段导言 → 按真源 `blocks.items[].members` 的次序，每个成员一节 `## <成员标签>` → 篇末 `## 参数` → 篇末 `## 论文出处`。成员节里自上而下：`### 物理` →（该对象有符号条目时）`### 变量名与 LaTeX 符号对照表` → `### 代码解析` → `### 工程` → `### 参数语境`；`### 工程` 里逐步骤 `#### <核定函数名>`，`### 参数语境` 里逐参数的写法见下。`##` 与成员节下的 `###` / `####` 各只出现一次，否则同名标题的锚点会拿到 `-1` 后缀、引用就点不开了。
- **物理 / 代码解析 / 工程三节**：物理节 = 成段叙述 + 恰好一个独立成行的公式；代码解析节 = 这一段的代码落点与它想说什么；工程节 = 逐步骤 `####`（标题 = 核定函数名）+ 该步的**代码与逐段解释**（先给这一步的落点与代码段，再逐段说它在算什么、依据哪条式子或拟合律、开关与分支怎么走、注释里写着的坑；代码段可以只给落点那几行、也可以把整个函数贴出来，长度不设上限），再给该对象自己核定的其余落点与说明 → `输入：` / `产出：`，**一条落点只印一次**（步骤小节里印过的从其余几条里扣掉；某个步骤的落点全被前面的步骤印过，就连它的标题一起省掉，不留空小节）。工程末尾按需接 `#### 口径分野`（有条目才出现，没有就不印那个子节）。
- **篇末 `## 论文出处`**：逐成员一组 —— `**<成员标签>**` 一行 + 该成员的**论文节号**（真源 `reviewSection`，形如 `- 论文节号：§3.6（\`docs/论文/…\`）`）与该成员名下条目的表。图上「论文出处」那条引用就锚在这一节上，谁点开都落在同一节、各自的节号在组内找得到。空集：某成员没有登记的出处，就在它那一组里写「本对象没有登记的论文出处。」；印出条目表的地方末尾必有一行「本地缺正文的条目：…」（表里都找得到正文就写「无」），只有节号、没有条目时不印空表也不写那句话。层的成员（`tgamma`）照常有一组，只是它名下没有条目，按空集话术写。
- **三张表与口径分野的正文**：顶层 `symbolMap` / `divergences` / `references`，每条带 `owner`（对象 id），是这批正文转录前的来源，图谱不再读它们——`symbolMap` 的列是「公式符号 / 含义 / 代码名（默认值）/ 进 C 的换算 / 落点」；`references` 的列是「公式或拟合律 / 原论文与作者 / 出处原文 / 代码位置 / 本地有无」（`local` 只是登记，md 里那一格按磁盘实际情况写）；`divergences` 的列是「对象 / 论文式 / 代码式 / 判据」。条目按 `owner` 落在各自那个成员节里，一处只印一次。
- **真源字段**：顶层 `docText`，键 = 对象 id（块的 `block:*` 与成员 id）；值 = `{ physics: [段落…], formula, input, output }`。图谱只读 `formula`（摘要位置那条式子，逐字转录进产物）；`physics` / `input` / `output` 同样是正文转录前的来源，正文以 md 为准。物理一节 MUST NOT 出现代码标识——文件名与目录名、函数名、参数名、行号、反引号包裹的片段。
- **落点**：成员取真源 `codeSites`，步骤取 `chain.stepSites`（逐计算单元核定；同一函数被两个量用到时按 `symbol` 复用），层的代码落点按真源 `block.codeAnchor.files` 给整文件锚点（行区间 = 1 到文件末尾；层的成员是常数，没有步骤落点可汇总）。落点**不限条数、不限跨度**——一条可以只盖几行，也可以盖住整个函数体乃至整份文件；旧口径的上限（每个成员至多两条、单条不超过 60 行、不许整文件区间）已废除，判据只剩「这条落点真的在那个文件的那几行上，区间里必须出现的标识真的出现」。每条落点 MUST 带一句说明（至少 20 字、以句号收尾）：落点回答**在哪一行**，说明回答**这一段在算什么**；说明是一句，正文不限于一句——工程节的职责是把这个量**怎么算出来**讲透。
- **成员节的 `### 参数语境`**：该对象名下的参数在这个成员上怎么做用。**一个参数在整篇里只在它第一次真正进算式的那一步讲全**——那一节按 `#### <参数名>`（标题就是这个参数名，与画布上那张标签卡同名）一章一个参数，写它从哪一步、哪个式子进来，动它哪些量跟着变，代码与论文口径差在哪。其余成员节不再重述来路，只按 `- **`<参数名>`**：…` 一行一句记它**在本步的后果**，并在节首一句「来路与落点见 `<主讲节>`」，读者知道去哪儿找全的。判据：把几节里同一个参数的话并排看，去掉来路句后剩下的还是同一件事，就是该收的重复；剩余的是不同的后果（开关类参数常如此，一开一关牵动几条链），就逐节写全。名下没有参数标签的成员写一行说明。
- **篇末 `## 参数`**：这一块携带的全部参数一张表，行序与画布上这块的「参数」卡一致，列是「参数 / 类别（`inputs.py` 的结构名）/ 在代码里做什么」——一行一个参数，说清它在这块里具体干什么、动它哪些量跟着变、哪些量不被它碰。与 `### 参数语境` 分工：这里按**块**给一份清点（一块的参数在同一处看全），逐**成员**的细读（从哪一步、哪个式子进来）留在成员节里，两处不重复抄。这一块不带参数时（如常数与网格、初始条件、引力扰动）写一段说明它为什么不带。
- **手写与门禁**：改散文 = 直接改 md。改完跑 `cd Graphify && npm run check:chain`，它核三件事——引用指向的 md 真实存在、每条引用的锚点能在该篇里定位到小节、盘上这 11 篇与真源的块表一一对应（多一篇 / 少一篇 / 放错位置都失败）；公式另跑 `node scripts/check-latex.mjs`（公式渲染不过即失败并指名文件与公式）。正文内容不再与真源重算对拍，形状与空集话术由改稿时守。
- **公式按 LaTeX 排版**：物理一节里的式子写成行内 `$...$` 与独立成行 `$$...$$`。正文里的星号要写成 `\*`（裸 `*` 成对出现会被 markdown 当成强调、把中间的符号吃掉）；数学里的星号写 `\ast` 或 `\star`（`f_\star`、`M_\star`）。
- **锚点**：引用里的 `anchor` = 那份文档里某个标题的 slug（口径同 `Graphify/src/lib/slug.ts`）——成员的笔记引用锚在它自己那一节的标题（即成员标签），块的笔记引用锚在 `#` 块标签，**论文出处那条引用锚在同一篇的 `## 论文出处` 上**。所以**改标题等于改锚点**，两处必须一起改（自检会查每条引用的锚点能否在该文档里定位到小节）。
- **引用怎么来的**：`docId` 是**相对 `docs/notes/` 的 POSIX 路径**（如 `physics-chain/modules/thermal.md`），服务端按目录扫描即可打开，**无需另行登记**。
