# 物理链页：设计口径与实现

先说这张图**是什么**、逻辑怎么定，再说**做出来长什么样**、由哪些部件构成。规则细节在 `README.md`（分级口径）。

## 一、这张图是什么

在 Graphify 里新开一页「物理图谱」，与现有的「画布」并列。

- 画布那一页讲**代码怎么搭起来的**：模块、驱动、数据流 —— 给改代码的人看。
- 这一页讲**物理怎么算出来的**：从"想知道的观测量"往下追问"谁决定它"，一直追到可以调的参数。

一页纸上分四层，**每层只讲一种语言**（硬规矩）：

| 层 | 讲什么 | 出现什么 | 不出现什么 |
| --- | --- | --- | --- |
| 观测量（根） | 这张图最后要解释的目标 | 亮温 δT_b、功率谱 P_21、τ_e、UV 光度函数 | — |
| 物理链（主体） | 量决定量：谁决定谁 | 自旋温度、电离分数、气体温度、加热率、源项…… | 代码名、文件名、行号 |
| 驱动量（叶子） | 能调、且真的改变物理的量 | f*、ζ、T_vir^min、L_X | — |
| 证据层（默认收起） | 怎么落到代码与论文 | 「源码」「文献」小标签页 + 「子图」按钮 | 选标签之前什么都不显示 |

## 二、图的逻辑（六条）

1. **自顶向下，根是亮温。** 根节点是 `δT_b`（21 cm 亮温）—— 那是代码真正产出的东西。同级出口还有 `τ_e` 与 UV 光度函数（代码直接给的诊断）；功率谱 `P_21` 标成"分析层"，因为代码不算它，它是拿波数对盒子做的统计。
2. **表面只有一条链，全是物理语言。** 每条箭头写"谁决定谁"，并带公式出处（Eq 号）。**代码怎么算出来的不进表面**：公式里是一个积分、代码里是"离散晕累加 + 积分器"，那就只在表面放**那个积分式**（父模块）；离散累加、积分器属"怎么算"，写进**模块文档里那个成员的步骤小节**（界面上不展开）。判据一句话：**表面是"算什么"，步骤是"怎么算"**。禁止把代码和公式并排放在同一层——并排会让同一个物理出现两个并列入口，读者无从判断哪个才是"这个量本身"。
3. **开关挂在箭头上。** 带开关的依赖画成虚线箭头 + 箭头上的虚线框，表示"这条依赖要不要算"。例如关掉 X 射线加热，`ε_heat → T_K` 这条就不走。
4. **有实现选择的环节，表面只写公式或过程的名字。** "用哪种质量函数（PS/ST/WATSON…）""用哪种传输函数""源项走哪条路径"这类选择**挂在这个环节上**（数据里是块的 `tags`，见 §八 第 7 条），每种选择之后的流程属"怎么算"、写进文档的步骤小节。表面上看到的就是那个公式本身，不被选项打断；表面模块也不因"有选项"而画虚线——**虚线框只用于"这个流程在某些配置下根本不存在"**（见第 5 条）。
5. **虚线框 = 这个模块/流程在某些配置下根本不存在**，并且必须写明"由哪个参数决定"。它不是"这个参数可选"的意思。
6. **参数两个入口。** 天体物理参数进抽屉（可检索、选中高亮相关模块与箭头）；实现选择挂块标签；数值/精度参数暂不纳入；宇宙学参数当常量，列一份清单即可。

7. **物理层里多种"种类"并存，用颜色区分。** 物理量（`T_S`、`x_HI`、`M_min`）、谱（`P_21`、物质功率谱 `P(k)`）、函数 / 关系（晕质量函数 `dn/dM`、光度函数 `φ(M_1500)`、标度关系）**都是物理层的东西**，一起出现在同一张图里，**用颜色区别种类**——不要因为它们"不是一类"就分层或另开页面。观测量（根）单独一色，块内成员用暗色。

8. **一张图里不许物理与工程夹杂。** 表面上**一个工程项都不许有**，哪怕只有一个最不起眼的（比如"整文件扫描"这类实现动作）。只要出现不属于这层的东西，就挂到一个**本层语言的名字**下面——挂到那个成员的步骤上，写进文档的步骤小节，不上图。判据：**这一项是不是物理过程 / 物理量 / 物理参数？** 是 → 本层；不是 → 归到成员的步骤（文档）。所以物理页里**不设"工程与装配"这类收起区块**（那等于把工程搬进这张图）；两张图各自纯粹，需要时用「源码」标签页跳过去。

## 三、页面形态

**首屏。** 进来看到一张从上往下的链图。最上面一张最显眼的卡片是 `δT_b`（21 cm 亮温）。它下面分出三条：电离分数、自旋温度、CMB 温度。再往下各自继续分——自旋温度那边分到 Ly-α 耦合、碰撞耦合、气体温度、X 射线加热；电离分数那边分到电离光子发射率与复合……一路分到最下面一排小卡片：f*、ζ、T_vir^min、L_X。

每张卡片三行：**物理名（大字）、一句人话（这一步在算什么）、它由谁决定（上游）**。没有文件名、没有行号、没有"Python 侧/后端"这类标签。

**点开一张卡片。** 旁边展开详情，顺序是：先物理——这一步在算什么、上游是谁、下游喂给谁、关键量是什么、涉及哪些参数（带默认值与取值范围）；然后是一条默认收起的小标签页：「**源码**」（点了才出现文件与行号，再点一下在编辑器里打开并高亮那段）、「**文献**」（只列代码注释里真实写着的出处，主要是拟合公式那类）；过程块上还有一个「**子图**」出口，进去看块内的成员与块内关系（不点不开）。FFT、滤波、条件表这些实现细节**不在图上**：它们写在模块文档里那个成员的步骤小节里。

**找参数。** 页上有个抽屉，输入"逃逸分数"或 `F_ESC10`，出来一张词条（中文名、代码代号、默认值、在哪几步起作用）。点它，图上相关的卡片与箭头**亮起来**，其余变淡；再点一下恢复。这就是"从一个参数反查流程"。

**看见开关。** 带开关的箭头画成虚线，旁边挂一个小框写着开关名；鼠标放上去显示"由 `USE_X_RAY_HEATING` 决定：关掉就没有这一项"。某个模块在某配置下整段不存在时，它的**框本身**画成虚线，并标着"由 `PHOTON_CONS_TYPE` 决定"。

**底部状态条。** 只报这一页的规模（物理过程、子过程、参数、论文各多少）和当前打开的是哪个对象。

**一句话验收**：在这一页上，任选一个物理量，能顺着箭头说清它由谁决定；任选一个参数，能高亮到它作用的每一步；任选一步，能一跳看到它的代码与文献。

## 四、页面构成

| # | 部件 | 内容 |
| --- | --- | --- |
| 1 | 链条数据 | 量、边、公式出处：4 个驱动量 / 34 个物理节点 / 54 条依赖边 |
| 2 | 量的算法落点 | 每个量与每条边的算法位置（含未定位标记） |
| 3 | 参数两条通道 + 开关挂到边上 | 参数 51 条（天体物理 29 / 驱动 8 / 数值 5 / 开关 9）；宇宙学常量列清单；实现选择挂块标签 |
| 4 | 论文挂到量上 | 只挂拟合公式那类 |
| 5 | 页面 | 链图 + 抽屉 + 高亮 + 虚线框 + 默认收起的证据出口 |
| 6 | 自检 | 生成物断言（`npm run check:chain`） |

**规模（现状）**：图上对象 **49**（11 个块 + 38 个物理量成员），另有 2 个段容器（`红移循环前` / `逐红移循环`）不入此数，层（常数与网格）不在段里、单独落在最上面那条带上；边 **77** 条 = 量间依赖 54（生成物 `stats.edges`）+ 块间 23（交付 21 + 跨红移回流 2）。模块文档 **11 篇**（一个块一篇，`find docs/notes/physics-chain/modules -name '*.md' | wc -l`，手写 md；成员在块那一篇里各占一节）；`npm run check:chain` **267** 项断言全绿。

**可延后**：每个参数的中文名与一句解释。它只影响"读起来舒服"，不影响框架；抽屉能用之后随时补。

## 五、边界（不做的事）

- 不做评估批注——合理性评估是使用者自己的工作。
- 不凭印象补论文或参数含义，缺就空着。
- 不把实现细节画到主链上（FFT、滤波、网格装配、缓存、并行 → 模块文档里那个成员的步骤小节或画布页）。
- 不加单位/量纲；宇宙学参数不建节点（当常量）。
