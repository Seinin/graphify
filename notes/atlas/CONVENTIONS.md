# atlas 维护契约（CONVENTIONS）

> 这份文件是**给维护者**的：它定义 atlas 怎么写、怎么改。
> **读者不需要读它**——请从 [README](README.md)（一页导览）进，或去 [INDEX](INDEX.md)（主题索引）查。

## 0. 一句话规约

**一层一个文件；每个文件只描述本层的一种概念单元；要提别的层，只写链接，不就地展开。**

- 上层不得解释下层怎么实现（只链接）。
- 下层不得重述上层怎么编排（只在自己需要时链接回去）。
- 概念越界不是"风格问题"，是**结构错误**：判据见 §5 自检清单。

## 3. 编号与锚点契约

### 3.1 编号

- 入口 `E1`、`E2`…（L0）；产物 `P01`、`P02`…（L0，两位补零）。
- 阶段 `S01`…`Snn`（L1）；子过程 `S07.3`（L2）；计算单元 `S07.3.1`（L3）；关键过程/关键量 `S07.3.1-a`（L4）。
- 子过程编号**只在其所属阶段内连续**，跨阶段重复无妨；计算单元同理。全仓唯一的完整地址是"阶段.子过程.单元"这个点分串。

### 3.2 标题格式与 slug

标题一律写成 `### 编号 名称`，**编号与名称之间只有一个半角空格**，名称中**不出现标点**（避免 slug 歧义）：

```markdown
### S13.4 多尺度滤波与塌缩分数积分
```

锚点按 GitHub slug 规则推导：转小写、删除 `.`、空格转 `-`、中文保留。

```markdown
[S13.4 多尺度滤波与塌缩分数积分](L2-subprocesses.md#s134-多尺度滤波与塌缩分数积分)
```

### 3.3 纯度口径的精确化（对"禁止概念越界"的可操作定义）

各层允许出现的**名字种类**如下；超出即违规：

| 层级 | 允许出现的名字 | 禁止出现的名字 |
| :--- | :--- | :--- |
| L0 | **对外公开符号名**：入口名（如 `run_coeval`）、产物结构名（如 `InitialConditions`）、参数结构名（如 `CosmoParams`）；**结构体的公开方法名**（如 `InputParameters.evolve_input_structs`、`GlobalEvolution.get_fields`、`CacheConfig.off`）；**§1.3 伪代码块内的编排层函数名与占位标识符**（名单在下方显式枚举）；**语言与数值库的通用调用**（如 `np.mean`、`getattr`）；**公开 API 函数名**（如 `setup_photon_cons`——它是对外导出名，不占下面的枚举名额）；**代码位置**：文件路径 + 该文件内的符号名，**仅限**每个词条的「代码位置」字段与文末「代码位置速查表」两处 | 上述允许项**以外**的任何文件路径与内部函数名；阶段名、子过程名、L4 意义上的关键变量名；行号 |
| L1 | 阶段名；链接到 L0 的 E/P | 函数名、文件路径、子过程名、变量名 |
| L2 | 子过程名；链接到 L0 的 P 或 L3 的单元；讲**编排关系**时（谁调谁、在哪一步交接什么）可写函数名 | 文件路径、行号、L4 意义上的关键变量名 |
| L3 | 文件名 + 函数/方法名（此处**才**允许出现代码符号）；链接到 L4 | 公式与变量取值 |
| L4 | 关键变量/常量名、关键过程名；必要时行内公式 | 上层调用关系、其它层的编排描述 |

> L0 之所以允许出现公开符号名，是因为**入口与产物本身就是 L0 的概念单元**；L0 禁止的是"跨进内部"——内部函数名、文件、阶段、子过程一律不得在 L0 出现。
>
> **两处豁免区（合计三处落点）**：① [L0 §1.3](L0-pipeline.md#13-三条时间流水线的伪代码对照) 的伪代码块——三条时间流水线的差别只在编排，不写函数名就讲不清，故按**显式枚举**放行**编排层的模块级函数名，共 5 个**：`_setup_ics_and_pfs_for_scrolling`、`_redshift_loop_generator`、`_run_lightcone_from_perturbed_fields`（三者是驱动层的包内私有函数）、`evolve_halos`（模块级公开名，不是私有）、`_get_photon_nonconservation_data`（定义在 `wrapper/photoncons.py`，由驱动层导入后使用）。同块内的**局部占位标识符与参数/选项名**（如 `ics`、`prev`、`out_redshifts`、`PHOTON_CONS_TYPE`）一并放行——它们是叙述用的临时名字，不是 L4 的「关键量」。**结构体的公开方法名与语言/数值库调用不算"内部函数名"，随上方允许列一并放行**，不必进枚举。② L0 每个词条的「代码位置」字段与文末「代码位置速查表」。豁免被限定在这三处（§1.3、代码位置、速查表），是为了让落点信息可预期——其余正文（结论、矩阵、依赖图、词条的其它字段）维持原纯度要求。

> 改 §1.3 的伪代码 = 改一段代码描述：必须回 `src/py21cmfast/drivers/` 逐条核对符号名与动作顺序，并同步本节的枚举名单——**多写一个名字就多一条豁免**，不允许顺手扩展。

### 3.4 跨层跳转的写法

- 只链接，不展开。上层提到下层内容，写成链接即可，不附加解释段落。
- 指向源码：相对 `docs/notes/atlas/` **上溯三层**，即 `../../../src/py21cmfast/<子路径>`。
- 指向既有权威文档：`../CODE_TOPOLOGY.md`、`../FDM.md` 等。
- 代码符号一律用行内代码（`` `ComputeIonizedBox` ``），不与链接混写。
- **L0 的「代码位置」**：字段里用行内代码写「路径 + 符号名」，**不放链接**（保持词条可扫读）；速查表里同一位置写成可点链接。两处都省略公共前缀 `src/py21cmfast/`（C 端因此写作 `src/IonisationBox.c`），前缀在速查表上方声明一次。

## 5. 层内纯度自检清单

写完一个层级文件后逐条核对，任一条不过即为结构错误：

1. 该文件出现的**每一个编号标题**都属于本层编号形式：L1 全是 `Snn`，L2 全是 `Snn.m`，L3 是 `Snn.m`（子过程锚点）或 `Snn.m.k`（计算单元），L4 全是 `Snn.m.k-a`；各级另允许用 `## Snn` 作阶段分组标题，不得出现其它形式的编号标题。
2. 该文件出现**每一个名字种类**都在 §3.3 的"允许"列内。
3. L0 全文检索：除文首的规约声明、[§1.3 的伪代码块](L0-pipeline.md#13-三条时间流水线的伪代码对照)（豁免名单见 §3.3）、每个词条的「代码位置」字段、文末「代码位置速查表」，以及**指向别层的链接文字**外，不出现 `阶段`、`子过程`、文件路径、内部函数名、行号。
4. L1 全文检索：除文首规约声明与指向别层的链接文字外，不出现函数名、文件路径。
5. L2 全文检索：除文首规约声明、跨层链接的 URL 片段，以及讲**编排关系**时显式写出的函数名外，不出现文件路径与行号（名字以子过程名与产物名为主）。
6. 每个词条都有指向"上一层"和"下一层"的链接（L0 的 E 只指向 L1；L4 无向下链接）。
7. 该文件没有任何一段文字在解释另一个层级的内部机制。
8. 该文件引用的每个锚点都能在目标文件里找到对应标题（见 §7 校验）。

## 10. 批量改写的安全写法（血泪教训）

用一次性脚本批量改这几份 md 时，**先把完整字符串拼好、再打开文件写入**：

```python
content = "\n".join(out)          # 先算好
with open(p, "w", encoding="utf-8") as f:   # 再打开
    f.write(content)
```

**不要**写成 `open(p, "w").write("\n".join(out))`：Python 会先执行 `open(..., "w")`（此刻文件已被截断），再计算 `.write()` 的参数；一旦参数计算抛异常，文件就永久停在 0 字节。2026-09-21 已因此把 `L3-units.md` 清空过一次。
