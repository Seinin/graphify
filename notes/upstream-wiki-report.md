## 0. 先把框架立起来：这个码在算什么

### 0.1 一句话

21cmFAST 是一个**半数值**的再电离仿真码：它**不跑流体力学**，而是从一个随机初始密度场出发，用**解析配方**（质量函数、标度关系）把"物质怎么成团"翻译成"星系在哪、发多少光"，再用**格点上的逐步积分**算出电离历史与 21cm 亮温。

它的输出单位是**盒**（cube）：边长若干 Mpc 的三维网格，格点数由分辨率参数决定。

### 0.2 主链：从参数到亮温的六个环节

这是本文后面**所有术语的坐标系**——任何一个新名词，都可以在这张表里找到它的位置、动机和产物。

| # | 环节 | 为什么要有它（动机） | 产出什么（形态） | 交给谁 |
| :--: | :--- | :--- | :--- | :--- |
| ① | **输入参数** | 一次运行的全部物理与数值设定 | 一套自洽参数集 | 所有后续环节 |
| ② | **初始条件** | 后续每个场都是从同一个随机密度场"长"出来的；它必须与观测的功率谱一致 | 高斯随机**密度场** + 由它派生的**位移场**（可选相对速度场） | ③ 微扰场、④ 晕 |
| ③ | **微扰场** | 初始场是"高红移的种子"，要把它**推到目标红移**才是那个时刻的宇宙 | 该红移的**密度场**与**视线速度场** | ⑤ 源项、⑥ 电离/热 |
| ④ | **晕** | 星系只住在塌缩成团的暗物质晕里，必须先知道"哪里有晕、多重" | **晕目录**（质量 + 坐标）或晕属性网格 | ⑤ 源项 |
| ⑤ | **源项** | 电离与加热需要的是"**每个格点上**有多少电离光子、多少恒星形成率、多少 X 射线"，而不是"哪里有晕" | **源项网格**（逐格辐射量）+ 尺度滤波后的 X 射线源箱 | ⑥ 电离、⑥ 热/自旋 |
| ⑥ | **电离与热** | 有了源，才算得出中性分数与自旋温度 | **电离盒**（中性分数等）+ **自旋温度盒**（Ts、xe、Tk） | 亮温 |
| ⑦ | **亮温** | 把密度、中性分数、自旋温度合成观测量 | **亮温盒**（+ 光学深度） | 输出 |

**旁路**（不在主链上）：光子守恒校准曲线（回灌到红移推进）、光度函数与光学深度诊断；**收尾形态**：见下。

### 0.3 同一批盒，三种"出片方式"

上面那条链算出的东西是**一批三维盒**。怎么把它交付出去，有三种方式（对外是三个入口）：

| 出片方式 | 回答的问题 | 交付形态 |
| :--- | :--- | :--- |
| **联合演化盒**（Coeval） | "某个宇宙时刻，整个三维宇宙长什么样" | 每个输出红移一份完整盒 |
| **光锥**（Lightcone） | "观测者沿视线看过去会看到什么"（频率轴 = 红移轴） | 把不同红移的切片拼成的观测形态 |
| **全局演化**（GlobalEvolution） | "整段历史的平均行为是什么" | 把盒压成一格，每个红移一个标量 |

三者的**物理计算完全共用**，差别只在参数怎么给、循环之外多做什么、结果怎么收——骨架见 [atlas L0 §1.3](atlas/L0-pipeline.md#13-三条时间流水线的伪代码对照)。

### 0.4 三主题站在链上的哪儿

```
① 参数 → ② 初始条件 → ③ 微扰场 → ④ 晕 → ⑤ 源项 → ⑥ 电离与热 → ⑦ 亮温 → 三种收尾
          └──── 主题三 ────┘        └──── 主题二 ────┘
└──────────────────────── 主题一：上面这一切"怎么被驱动" ────────────────────────┘
```

- **主题一**不是某一环的物理，而是**编排层**：谁在什么顺序上调用谁、结果怎么缓存与交付（DeepWiki 的 Running Simulations / Coeval Cubes / Lightcones / Caching / Output Structures）。
- **主题二**是第 ④–⑤ 环：从"有多少晕"到"每格有多少辐射"（Halo Physics / Halo Mass Functions / Scaling Relations / Stochastic Halo Sampler）。
- **主题三**是第 ② 环，外加第 ③ 环的一半（Initial Conditions & Perturbation Fields / Input Parameters）。

## 2. 主题一 · 三种运行模式：怎么驱动上面的链

### 2.1 位置

它不在链的某一环里，而是**横跨整条链的编排层**：负责把 ① ~ ⑦ 按顺序调起来、把结果按需要的形式交付。

### 2.2 动机：为什么必须有三种，而不是一种加开关

因为三种科研问题要的"形态"根本不同：

- 要算**功率谱、气泡尺寸分布、形态统计**，必须拿到"**同一时刻**的完整三维盒"——不同红移的场混在一起没有物理意义（这就是 Coeval = co-eval，同时刻的由来）。
- 要和**观测**比较，就必须知道"望远镜沿视线看过去看到什么"：频率轴对应红移轴，也就是**视线方向的过去**；所以要把不同红移的盒按观测几何切片拼起来。
- 只关心**全球平均历史**（再电离史、平均亮温、光学深度）时，仍然需要一个**平均值**——只是这个平均值不必从三维场里平均出来：它可以由**功率谱/质量函数的解析积分**直接给出（机制见 §2.4 的 (c)）。所以"压成一格"省掉的是 $N^3$ 的**空间场**，代价是**必须把空间涨落用次网格闭合买回来**。

### 2.3 产物

就是 §0.3 表里那三种：演化快照 / 光锥 / 历史曲线。**动机决定了形态**：想清楚"要哪一种形态"，就选哪一个入口。

### 2.4 怎么工作（骨架已写过，此处只补 DeepWiki 独有的两层 + 一处易误读的澄清）

公共备料与逐红移循环、以及三者在参数/额外动作/收尾上的差异，见 [atlas L0 §1.3](atlas/L0-pipeline.md#13-三条时间流水线的伪代码对照)。DeepWiki 在这两层之外讲清了两件事，是既有文档没有的：

**（a）两组红移的分工**——这是理解"为什么改参数会改变结果"的关键：

| | 节点红移（`node_redshifts`） | 输出红移（`out_redshifts`） |
| :--- | :--- | :--- |
| 归属 | 输入参数的一部分 | 联合演化盒入口的入参 |
| 作用 | 物理**演化**在哪几个红移上发生 | 只决定**返回**哪几个 |
| 改它会改结果吗 | **会**：自旋温度、X 射线加热、Lyα 耦合都依赖历史积分 | 不会，纯筛选 |
| 不指定时 | 需要演化时自动生成（对数间隔的一段红移） | 等于节点红移 |

需要"多红移推进"的条件（两者一致）：开启自旋温度涨落、非均匀复合、迷你晕三者之一。

**（b）缓存与内存**——它们**不是**物理的一部分，而是"长链条算一次要很久"逼出来的工程安排。所以放在下一小节，作为"为什么这样设计"的下沉，而不是术语铺陈。

**（c）"一格代表整个宇宙"凭什么成立：平均值不是从盒里平均出来的**（本仓核对 `已核`）

这是最容易误读的一点，值得单列。E3 要的是**全局平均**（平均电离分数、平均电子分数与温度、平均亮温）。这些量 E1 也能给——对每个快照取盒均值即可（光锥与快照对象里的"按红移均值"就是这么来的）——但那是**用 $N^3$ 的代价顺带得到的副产品**。

E3 换了个来源：它把方程里每一项的**平均值直接用解析积分算出来**，所以只要一格。本仓可核对的三处：

1. **0-D 电离盒**：全局再电离历史是由"对质量函数积分得到的**平均电离光子产出**"解出填充因子，而不是平均某个场（代码路径是 `compute_global_reionization_at_z` → `evaluate_Nion_z(...)`）。
2. **平均恒星形成率密度**：0-D 自旋温度演化用的是逐红移**解析求出**的均值（`EvaluateSFRD(...)` 一族），直接当源项。
3. **闭合项**：复合依赖 $\langle x_e^2\rangle$（二阶矩，一阶矩封闭不了），必须参数化——本仓的复合汇项里显式乘了 `CLUMPING_FACTOR`。

**这笔交换的代价**（也正是"为什么 E3 必须关掉游程集与光子守恒校正"的原因）：空间涨落、密度—电离协方差、气泡形态一概没有。游程集算法与光子守恒校正是**为空间场与气泡而存在**的，0-D 里没有服务对象。反过来，**E1 的盒均值是校核 E3 最自然的基准**——两者不一致时，先怀疑闭合参数（如 clumping factor），而不是怀疑 E1。

### 2.5 下沉：为什么需要缓存，以及缓存按什么分级

动机：一次运行要算几十个红移 × 每红移一整套盒，中途断了、或者只想改天体物理参数重跑，都希望能**复用**已经算好的部分。

因此每个产物按"它到底依赖哪些参数"分成三级路径（本仓核对 `已核`，模板逐字一致）：

| 级别 | 依赖 | 谁用 | 结果 |
| :--- | :--- | :--- | :--- |
| 最粗 | 宇宙学 + 数值 + 种子 | 初始条件 | 同一宇宙学下的所有运行**共享** |
| 中间 | 再加红移网格 | 微扰场、晕目录、微扰晕目录 | 同一演化网格下共享，**与天体物理无关** |
| 最细 | 再加天体物理标志 | 电离盒、自旋温度盒、亮温盒、源项网格 | 每个参数组合各存一份 |

> DeepWiki 只把微扰场归到中间级，漏了晕目录与微扰晕目录 → `与既有文档冲突`。

每级路径由四组参数的哈希拼成（物质/宇宙学、种子、红移网格、天体物理标志），实现上取 **MD5**。

**策略**：可一次性声明"这次缓存什么"（全开 / 全关 / 只缓存循环外的重活 / 只缓存重启所需），本仓的命名构造核对：全开、全关、只缓存循环外、只缓存最后一步四个都在；**DeepWiki 另外提到的 `dmfield()` 不存在** → `与既有文档冲突`。

**完备性**：判断"某个红移节点是否算齐了"是断点续算的前提——判决看该红移必需的几种盒是否都已存在（某几种按开关条件计入）——`已核`。

### 2.6 下沉：为什么需要管内存，怎么管

动机：一个 $256^3$ 的双精度盒就是几百 MB，而链条上同时要挂多个红移的盒。

三条安排（均 `已核`）：

1. **数组状态机**：每个数组在"未分配 / 内存中有值 / 已推给 C / 已落盘"之间迁移，可随时"卸掉值"回到未分配；对应一组显式的状态方法。
2. **按步裁剪**：初始条件在进入微扰场阶段前、进入自旋温度阶段前各裁剪一次，只保留下一步真正需要的数组。
3. **光锥只留两份**：光锥是逐红移增量填充的，任意时刻只需保留**相邻两个**盒（当前与上一个，插值用），其余随算随卸。

### 2.7 下沉：光锥的断点续算

动机：光锥是"边算边填"的长任务，中断代价高。

于是它把进度写在光锥文件里（已完成到哪个节点红移、填到视线方向的哪个位置），重跑时从断点继续；读入部分光锥时可以**保留边界缓冲像素**（红移空间畸变要用），最后再裁掉。字段与读入接口在本仓均存在——`已核`。

## 3. 主题二 · 晕与源项：把"物质成团"翻译成"逐格辐射"

### 3.1 位置

主链第 ④–⑤ 环，夹在"微扰场"和"电离/热"之间。

### 3.2 动机：为什么必须有这一环

电离阶段要回答的是"**这个格点被电离了吗**"，判据里最核心的一项就是"**这个格产生了多少电离光子**"。但光子不由密度场直接给出——光子来自星系，星系住在**塌缩成团的暗物质晕**里。所以必须先完成两次翻译：

$$
\text{密度场} \longrightarrow \text{有多少晕、多重} \longrightarrow \text{每个晕产多少辐射} \longrightarrow \text{每格多少辐射}
$$

这三步分别对应本节的三类技术：**质量函数**（多少晕）、**标度关系**（每个晕产多少光）、**采样器与网格积分**（怎么摊到格子）。

### 3.3 产物与消费者

产出的是**源项网格**：每一行是"一格上的某个辐射量"，列包括电离光子数、恒星形成率、X 射线、逃逸加权恒星形成率、迷你晕恒星形成率（**本仓 `已核`**）。消费方是两处：电离阶段直接读"电离光子场"与"逃逸加权恒星形成率"；热与自旋温度阶段读"恒星形成率"与"X 射线"，且后者要先经**按球壳厚度递增的滤波**变成 X 射线源箱（P07）——因为 X 射线能自由程长，加热强度取决于周围多大范围内的源。

### 3.4 第一步怎么工作：多少晕 → 质量函数

**位置与动机**：它回答"给定质量尺度（和给定环境密度），单位体积内有多少个晕"。之所以既要"无条件"又要"条件"两种形式：前者用于全局平均（比如整盒的平均塌缩分数），后者用于"**某个格点**周围密度偏高时，那里应该多出多少晕"——这正是把晕的分布与密度场联系起来的桥梁。

**产出**：一个可积的函数（每单位质量/对数质量的晕数），它**本身不产生网格**，只是被后面的积分与采样调用。

**怎么工作**（DeepWiki 给公式、本仓给同名实现，全部 `已核`）：四种无条件形式 + 三种条件形式。术语在此才出现：

| 形式 | 直觉 | 本仓实现 | 参数（本仓逐字） |
| :--- | :--- | :--- | :--- |
| Press-Schechter | 最简单的球塌缩 | `dNdlnM_PS` | 常值塌缩阈值 |
| Sheth-Tormen | 椭球塌缩 + **移动势垒** | `dNdlnM_st` | 三个拟合系数 0.73 / 0.34 / 0.81 |
| Watson FOF（及红移演化版） | 由模拟拟合的普适形式 | `dNdlnM_WatsonFOF` / `dNdlnM_WatsonFOF_z` | 0.282 / 2.163 / 1.406 / 1.210 |
| Delos | 与条件形式自洽的较新模型 | `dNdlnM_Delos` | $f(\nu)=0.519\nu^{0.582}e^{-0.469\nu^2}$，常值势垒 1.5 |
| 条件形式 | "给定尺度上密度偏高/偏低时" | `dNdM_conditional_EPS` / `dNdM_conditional_ST` / `dNdlnM_conditional_Delos` | 移动势垒的条件式需对 $\sigma$ 做泰勒展开（`st_taylor_factor`） |

### 3.5 第二步怎么工作：每个晕产多少光 → 标度关系

**位置与动机**：质量函数只说"有多少晕"，而辐射量取决于晕里的**星系**。把"晕质量"翻译成"恒星质量 → 恒星形成率 → 电离光子 / X 射线"，就是标度关系（晕物理页的核心）。

**产出**：每个晕的一组属性（恒星质量、恒星形成率、电离光子数、金属性、X 射线光度）。这些属性有两个消费者：**采样器**（逐晕赋值）与**质量函数的被积函数**（在格点上积分时，每个质量处都要乘一次属性）。

**怎么工作**（本仓函数名 `已核`）：

- 质量 → 恒星质量：`get_halo_stellarmass()`，含对数正态散射（散射用相关系数化的随机数，保持跨快照相关）。
- 恒星质量 → 恒星形成率：`get_halo_sfr()`。
- **电离光子的出逃比例**：逃逸分数按晕质量取幂律，上限截断到 1；参数 `F_ESC10` / `ALPHA_ESC` 本仓存在（迷你晕另有 7 次方的归一化参数，其默认值未取）。**动机**：不是所有电离光子都能逃离星系进入星系际介质，这个比例直接决定电离效率。
- **金属性 → X 射线**：金属性由 `get_halo_metallicity()` 给出，再由 `lx_on_sfr_Lehmer()` 把"恒星形成率 × 金属性"换成 X 射线光度，最后 ACG 与 MCG 两套贡献各自带散射相加（函数名 `已核`，公式细节与文献归属记 `未核`）。

**冲突点**：DeepWiki 写的金属性是 $\log_{10}$ 形式，本仓实际是一个带拟合系数的复合式 → 记 `与既有文档冲突`。

$$
Z_{\rm out} = 1.23 \times \left[1 + \left(\frac{M_\star}{1.28825\times10^{10}\,(\mathrm{SFR}/[\mathrm{yr}])^{0.56}}\right)^{-2.1}\right]^{-0.148} \times 10^{-0.056\,z+0.064}
$$

### 3.6 第三步怎么工作：怎么摊到格子上（两条路线 + 两套工具）

**两条路线**（取决于源模型的"源定义在哪"）：

- **拉格朗日型**：先在**初始条件网格**上按条件质量函数积分、得到每个初始格点的属性，再用位移场搬到欧拉网格。来源可以是**解析采样**（随机抽样出一个个晕）或**固定网格积分**。
- **Eulerian 型**：直接在平滑后的密度网格上积分条件质量函数、乘以 $(1+\delta)$ 得到属性。

**两套工具**：

- **抽样器**（用于"解析采样"路线）：把"期望有多少个晕"变成"实际抽出的晕表"（质量 + 位置 + 属性随机数），共有四种方法（按数量抽 / 按质量抽 / Sheth-Lemson 分割 / 二叉树分裂），本仓四个函数均在——`已核`。
  **两条 DeepWiki 没写、但极易踩的**：① 分派的第一条判据是"**只要不是从目录采样，就一律用按数量抽**"，所以 `SAMPLE_METHOD` 在网格情形形同虚设；② Python 侧 `SAMPLE_METHOD` 是**字符串**枚举（默认按质量抽），而 C 侧按整数比较。
  **冲突点**：DeepWiki 把 0/1 两个编号与函数名对调了 → `与既有文档冲突`。
- **网格积分**（用于固定网格路线）：在质量上对"质量函数 × 标度关系"积分。三种方法（自适应求积 / 预置高斯-勒让德节点 / 解析近似），选项名本仓核对 `已核`；其中解析近似**只在 Press-Schechter 族**下成立。高过密区会从固定节点切到自适应求积，这条未回源确认阈值——记 `未核`。

**一处本仓查不到的符号**：DeepWiki 把 `HALO_STOCHASTICITY` 列为"随机采样的总开关"，本仓全库无此名 → `未核`（可能上游新增，也可能 AI 幻觉；本仓的等价控制是源模型与采样方法的组合）。

## 4. 主题三 · 初始条件与微扰场：链的起点

### 4.1 位置

主链第 ② 环（初始条件）与第 ③ 环的一半（把初始密度推到某个红移）。

### 4.2 动机：为什么起点是一个"随机"场

因为宇宙学初始扰动是**高斯随机场**：它的统计性质（功率谱）由宇宙学参数给定，具体的实现由随机种子给定。这带来两个直接后果：**同一个种子必得同一套结果**（复现性），以及**所有后续结构都从这一个场长出来**（所以它的分辨率、随机性、边界都影响全局）。

### 4.3 产物与消费者

初始条件盒里装两样东西：

- **密度场**：低分辨与高分辨各一份（低分辨用于大多数格点计算，高分辨用于需要精度的位移与降采样）。
- **位移场**：由密度场导出的速度（可理解为"粒子往哪走"），一阶必给、二阶可选；开启相对速度时另存一份**暗物质—重子相对速度**（它影响早期冷却与恒星形成）。

消费者是微扰场阶段与晕阶段——前者要密度与位移，后者要密度与速度。

### 4.4 怎么工作：三步

**第一步 · 抽样**（本仓核对 `已核`，公式逐字）：在傅里叶空间逐模抽样——对每个波数取功率谱值，然后各抽两个标准正态随机数当实部与虚部，模幅乘上"体积 × 功率谱 / 2"的平方根；抽完补**厄米共轭**（保证逆变换回实空间是实场），再逆变换得到密度场。

**第二步 · 位移场**：一阶位移场（Zel'dovich）由密度场在傅里叶空间乘梯度算子得到；二阶（2LPT）由势的拉普拉斯组合得到，用来在对角分量上避免网格各向异性。相对速度场则在开启时按对应的功率谱单独加权构造。函数名本仓核对 `已核`。

**第三步 · 交给微扰场**（详见 [INITIAL_CONDITIONS.md](INITIAL_CONDITIONS.md) 与 [CODE_TOPOLOGY §微扰场与速度](CODE_TOPOLOGY.md#微扰场与速度)）：微扰场阶段把初始密度**推到目标红移**——线性算法就是"乘增长因子"，非线性算法用位移场把质量搬到目标网格，随后可选降采样、平滑与钳位，并算出视线速度（三维速度由开关决定）。这一层的三种内存/精度安排（是否高分辨位移、是否 2LPT、是否保留三维速度）在本仓 `已核`。

### 4.5 一处必须点名的分歧：$\delta$ 怎么随红移演化

DeepWiki 写：

$$
\delta(\mathbf{x},z) = \frac{D(z)}{D(z_{\rm init})}\,\delta(\mathbf{x},z_{\rm init})
$$

**本仓不是这样**：线性分支的实现是"初始密度 × 增长因子"，而增长因子在本仓被归一化为 $z=0$ 时为 1，且抽样的模幅只按 $z=0$ 的功率谱给（**不含**任何增长因子）。所以本仓的等价表述是

$$
\delta(\mathbf{x},z) = D(z)\,\delta(\mathbf{x},z{=}0)
$$

即"初始条件盒里的密度场，本身就是线性外推到今天的场"，**没有** $1/D(z_{\rm init})$ 这个因子。照 DeepWiki 的式子理解，会系统性地把结果读偏。该行记 `与既有文档冲突`。
