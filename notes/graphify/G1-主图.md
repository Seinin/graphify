## 二 核心入口与主干流程

### 主干一览

图上真实的连线（`→` 均为有向边，`[ ]` 里是边的标签 = 关系名或产物名）：

| # | 从 | 边 | 到 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | 入口 · 命令行 / Python API | `[命令行]` | 入口 A · 21cmfast run ics | 分支 A 的左支 |
| 2 | 入口 · 命令行 / Python API | `[Python API]` | 入口 B · 三个顶层驱动 | 分支 A 的右支 |
| 3 | 入口 B · 三个顶层驱动 | `[调用]` | _setup_ics_and_pfs_for_scrolling | 备料的统一入口 |
| 4 | _setup_ics_and_pfs_for_scrolling | `[备料]` | compute_initial_conditions | 产物 P02 在这里诞生 |
| 5 | compute_initial_conditions | `[ICs]` | setup_photon_cons | 光子守恒校准的装配 |
| 6 | setup_photon_cons | `[校准曲线]` | perturb_field × len(all_redshifts) | 校准曲线回灌到每个红移 |
| 7 | perturb_field × len(all_redshifts) | `[晕目录[]]` | evolve_halos（仅 has_discrete_halos） | **条件边**（分支 F） |
| 8 | perturb_field × len(all_redshifts) | `[微扰场[iz]]` | 每轮入口 | 进入红移循环 |
| 9 | evolve_halos（仅 has_discrete_halos） | `[晕目录[iz]]` | 每轮入口 | **条件边**（分支 F） |
| 10 | 每轮入口 | `[微扰场[iz]]` | ① compute_halo_grid | 每轮的第一件事 |

**一句话主干**：`参数（P01）→ 备料（P02 初始条件 / P03 微扰场 / 可选 P04 晕目录）→ 逐红移循环（P06→P07→P08→P09→P10）→ 收尾（P11/P12/P13）→ 落盘`。

### ① 入口层

#### 入口 · 命令行 / Python API

- **作用与意义**：唯一的对外入口面——命令行子命令与 Python API 都从这里进来；它自己不做计算，只把参数装配好并分派到两条路。
- **对应阶段**：[S01 参数装配与模板](../atlas/L1-stages.md#s01-参数装配与模板)（`S01.4` 命令行与全局配置）、[S02 驱动编排](../atlas/L1-stages.md#s02-驱动编排)
- **输入 / 产出**：输入命令行与模板取值；产出 [P01 输入参数集](../atlas/L0-pipeline.md#p01-输入参数集)（逻辑产物，不落盘）。
- **关键位置**：`cli.py` 的 `run` 命令组：`ics`（入口 A）、`coeval` / `lightcone`（入口 B）、`params`（只打印参数）。
- **分支**：见 [分支 A](#分支-a-两条入口命令行-run-ics-与-python-api)。

### ② 编排层（选一条）

#### 入口 A · 21cmfast run ics

- **作用与意义**：只算初始条件的那条路——`21cmfast run ics` 一次跑出 [P02 初始条件](../atlas/L0-pipeline.md#p02-初始条件) 就结束，用来先备好 ICs 或单独检查它。
- **对应阶段**：[S09 初始条件](../atlas/L1-stages.md#s09-初始条件)（展开见 [G3 初始条件](G3-初始条件.md)）、[S03 缓存与持久化](../atlas/L1-stages.md#s03-缓存与持久化)
- **输入 / 产出**：输入 P01；产出 P02，并按 `CacheConfig.initial_conditions` 落盘。
- **关键位置**：`cli.py` 的 `ics` → `drivers/single_field.py` 的 `compute_initial_conditions`。
- **参数**：见 [§五](#五-模块参数与标签)（与 G3 同一批）。

#### 入口 B · 三个顶层驱动

- **作用与意义**：正式推进的那条路——同一套"备料 + 逐红移循环"骨架，供三种收尾形态各跑一遍。**本模块可进入**：双击展开为 [G2 入口 B](G2-入口B.md)。
- **对应阶段**：[S02 驱动编排](../atlas/L1-stages.md#s02-驱动编排)（`S02.1`–`S02.6`）
- **输入 / 产出**：输入 P01（以及备料阶段产出的 P02/P03/P04）；产出 P11 演化快照 / P12 光锥 / P13 全局演化历史。
- **关键位置**：`drivers/coeval.py` 的 `run_coeval` / `generate_coeval`、`drivers/lightcone.py` 的 `run_lightcone` / `generate_lightcone`、`drivers/global_evolution.py` 的 `run_global_evolution`。
- **分支**：见 [分支 B](#分支-b-三条时间流水线)。

#### _setup_ics_and_pfs_for_scrolling

- **作用与意义**：三条流水线共用的**备料**：把初始条件与多数红移的微扰场一次性备好，避免在红移循环里重复计算；这是主图上"备料层"的总闸门。
- **对应阶段**：[S02.1 初始条件与微扰场准备](../atlas/L2-subprocesses.md#s021-初始条件与微扰场准备)（单元 [S02.1.1](../atlas/L3-units.md#s0211-_setup_ics_and_pfs_for_scrolling)）
- **输入 / 产出**：输入 P01；产出 P02 初始条件、多数红移上的 P03 微扰场，以及（条件）P04 晕目录与光子守恒校准数据。
- **关键位置**：`drivers/coeval.py` 的 `_setup_ics_and_pfs_for_scrolling`（内部顺序：`compute_initial_conditions` → `prepare_for_perturb` → `setup_photon_cons` → 逐红移 `perturb_field` → `evolve_halos` → `prepare_for_spin_temp`）。
- **参数**：`MINIMIZE_MEMORY`（内存回收）、`PHOTON_CONS_TYPE`、`PHOTONCONS_CALIBRATION_END`（校验）。
- **分支**：见 [分支 D](#分支-d-光子守恒-photon_cons_type)、[分支 F](#分支-f-离散晕-has_discrete_halos)。

### ③ 备料层（只做一次，与红移无关）

#### compute_initial_conditions

- **作用与意义**：一切产物的起点——抽一份高斯随机密度场并推出高低分辨密度与位移速度。**本模块可进入**：双击展开为 [G3 初始条件](G3-初始条件.md)。
- **对应阶段**：[S09 初始条件](../atlas/L1-stages.md#s09-初始条件)（`S09.1`–`S09.5`）
- **输入 / 产出**：输入 P01；产出 [P02 初始条件](../atlas/L0-pipeline.md#p02-初始条件)。
- **关键位置**：`drivers/single_field.py` 的 `compute_initial_conditions` → C 侧 `src/InitialConditions.c` 的 `ComputeInitialConditions`。
- **参数**：见 [G3 §五](G3-初始条件.md#五-每步参数与标签)。

#### setup_photon_cons

- **作用与意义**：把"光子守恒"校准曲线装配好，供后续每个红移校正实际所用的红移与密度增长；`no-photoncons` 时它什么都不做。
- **对应阶段**：[S02.1](../atlas/L2-subprocesses.md#s021-初始条件与微扰场准备)、装配实现见 [S04.3 光子守恒校准装配](../atlas/L2-subprocesses.md#s043-光子守恒校准装配) 与 [S16.1 全局光子守恒校准](../atlas/L2-subprocesses.md#s161-全局光子守恒校准)
- **输入 / 产出**：输入 P02（以及 P01）；产出 [P16 光子守恒校准曲线](../atlas/L0-pipeline.md#p16-光子守恒校准曲线)（C 侧全局状态，不落盘）。
- **关键位置**：`wrapper/photoncons.py` 的 `setup_photon_cons`。
- **参数**：`PHOTON_CONS_TYPE`（四档分支）、`PHOTONCONS_CALIBRATION_END`（校准红移下限，默认 3.5）。
- **分支**：见 [分支 D](#分支-d-光子守恒-photon_cons_type)。

#### perturb_field × len(all_redshifts)

- **作用与意义**：把初始密度场推到每个目标红移，得到逐红移的微扰场（主图上写成 `× len(all_redshifts)` 提醒它一份红移一份）。
- **对应阶段**：[S10 微扰场与速度](../atlas/L2-subprocesses.md#s10-微扰场与速度)（`S10.6` 顶层编排）
- **输入 / 产出**：输入 P02；产出 [P03 微扰场](../atlas/L0-pipeline.md#p03-微扰场)（每个红移一份）。
- **关键位置**：`drivers/single_field.py` 的 `perturb_field` → `src/PerturbedField.c`。
- **参数**：`KEEP_3D_VELOCITIES`（是否额外算水平速度分量）、`PERTURB_ALGORITHM`（决定是否做归一化）、`DIM` / `HII_DIM` / `BOX_LEN`。

#### evolve_halos（仅 has_discrete_halos）

- **作用与意义**：按反红移序逐级识别离散晕，并把上一级结果作为后代传下去，使晕在红移方向上连续；**只在离散晕抽样打开时才走这一步**（名字里的"仅"就是条件）。
- **对应阶段**：[S02.2 晕演化与位移编排](../atlas/L2-subprocesses.md#s022-晕演化与位移编排)、[S11 晕目录与位移](../atlas/L2-subprocesses.md#s11-晕目录与位移)
- **输入 / 产出**：输入 P02/P03 与 P01；产出 [P04 晕目录](../atlas/L0-pipeline.md#p04-晕目录)（每个红移一份）。
- **关键位置**：`drivers/coeval.py` 的 `evolve_halos` → `drivers/single_field.py` 的 `determine_halo_catalog`。
- **参数**：`SOURCE_MODEL`（决定 `has_discrete_halos`）、`HMF` 与 `INTEGRATION_METHOD_ATOMIC` / `INTEGRATION_METHOD_MINI`（质量函数与积分路径）、`FDM` / `HMF_FINDEX`（FDM 修正）。
- **分支**：见 [分支 C](#分支-c-源模型-source_model)、[分支 F](#分支-f-离散晕-has_discrete_halos)。

### ④ 红移循环（每红移重复，z 由高到低）

#### 每轮入口

- **作用与意义**：红移循环一行的入口：把这一轮的微扰场（与可选的晕目录）装好，交给下面五个单场计算；它本身不做物理。
- **对应阶段**：[S02.3 红移递减推进循环](../atlas/L2-subprocesses.md#s023-红移递减推进循环)（单元 [S02.3.1](../atlas/L3-units.md#s0231-_redshift_loop_generator)）
- **输入 / 产出**：输入 P03（与条件 P04）；产出交给 ① 的 HaloBox 输入。
- **关键位置**：`drivers/coeval.py` 的 `_redshift_loop_generator` 循环体开头（逐红移 `load_all`）。
- **参数**：无（只做装载；参数在下游各步生效）。

#### ① compute_halo_grid

- **作用与意义**：把晕折算成网格上的源项——电离光子、恒星形成率、X 射线光度（产物就是 HaloBox）。
- **对应阶段**：[S12 天体物理源](../atlas/L2-subprocesses.md#s12-天体物理源)（`S12.1` 标度关系、`S12.2` 源项网格化）
- **输入 / 产出**：输入 P03（与条件 P04）；产出 [P06 源项网格](../atlas/L0-pipeline.md#p06-源项网格)。
- **关键位置**：`drivers/single_field.py` 的 `compute_halo_grid` → `src/HaloBox.c`。
- **参数**：`SOURCE_MODEL`、`HII_DIM`、`Z_HEAT_MAX`、`USE_TS_FLUCT`、`USE_MINI_HALOS`、`PHOTON_CONS_TYPE`、`INTEGRATION_METHOD_*`、`HMF`、`FDM` / `HMF_FINDEX`、`M_TURN`、`USE_UPPER_STELLAR_TURNOVER`。
- **分支**：见 [分支 C](#分支-c-源模型-source_model)。

#### ② compute_xray_source_field

- **作用与意义**：把源项按环状壳层预滤波成 X 射线源箱，供自旋温度步使用；**只在自旋温度涨落打开时才走**。
- **对应阶段**：[S14 热与自旋温度](../atlas/L2-subprocesses.md#s14-热与自旋温度)（`S14.3` 源场多尺度滤波、`S14.4` X 射线频率积分表）
- **输入 / 产出**：输入 P06 源项网格；产出 [P07 X 射线源箱](../atlas/L0-pipeline.md#p07-x-射线源箱)。
- **关键位置**：`drivers/single_field.py` 的 `compute_xray_source_field` → `src/SpinTemperatureBox.c`。
- **参数**：`M_TURN`、`N_STEP_TS`、`R_MAX_TS`、`BOX_LEN`、`HII_DIM`、`Z_HEAT_MAX`、`USE_TS_FLUCT`、`USE_MINI_HALOS`、`PHOTON_CONS_TYPE`。
- **分支**：见 [分支 E](#分支-e-自旋温度涨落-use_ts_fluct)。

#### ③ compute_spin_temperature

- **作用与意义**：在逐格点上解自旋温度与电离度、动理学温度的演化（产物 TsBox）；**只在自旋温度涨落打开时才走**。
- **对应阶段**：[S14 热与自旋温度](../atlas/L2-subprocesses.md#s14-热与自旋温度)（`S14.6` 逐格点自旋温度演化）
- **输入 / 产出**：输入 P07；产出 [P08 自旋温度盒](../atlas/L0-pipeline.md#p08-自旋温度盒)。
- **关键位置**：`drivers/single_field.py` 的 `compute_spin_temperature` → `src/SpinTemperatureBox.c`。
- **参数**：`USE_TS_FLUCT`、`Z_HEAT_MAX`、`HII_DIM`、`SOURCE_MODEL`、`USE_MINI_HALOS`、`PHOTON_CONS_TYPE`、`MINIMIZE_MEMORY`。
- **分支**：见 [分支 E](#分支-e-自旋温度涨落-use_ts_fluct)。

#### ④ compute_ionization_field

- **作用与意义**：用塌缩分数与游程集判据决定每个格点电离没有，再扣复合与自屏蔽（产物 IonizedBox）。
- **对应阶段**：[S13 电离与复合](../atlas/L2-subprocesses.md#s13-电离与复合)（`S13.4` 多尺度滤波与塌缩分数积分、`S13.5` 游程集判据、`S13.6` 复合与自屏蔽）
- **输入 / 产出**：输入 P06 源项网格（与条件 P08）；产出 [P09 电离盒](../atlas/L0-pipeline.md#p09-电离盒)。
- **关键位置**：`drivers/single_field.py` 的 `compute_ionization_field` → `src/IonisationBox.c`。
- **参数**：`SOURCE_MODEL`、`HII_DIM`、`Z_HEAT_MAX`、`USE_TS_FLUCT`、`PHOTON_CONS_TYPE`、`USE_EXP_FILTER`、`HII_FILTER`、`CELL_RECOMB`、`USE_MINI_HALOS`、`F_ESC10`、`HII_EFF_FACTOR`、`MINIMIZE_MEMORY`。
- **分支**：见 [分支 C](#分支-c-源模型-source_model)、[分支 D](#分支-d-光子守恒-photon_cons_type)。

#### ⑤ brightness_temperature

- **作用与意义**：把密度、中性分数、自旋温度合成 21-cm 亮温（主链的终点，唯一直接可观测的量）。
- **对应阶段**：[S15 亮温输出](../atlas/L2-subprocesses.md#s15-亮温输出)
- **输入 / 产出**：输入 P09 电离盒（与条件 P08）；产出 [P10 亮温盒](../atlas/L0-pipeline.md#p10-亮温盒)。
- **关键位置**：`drivers/single_field.py` 的 `brightness_temperature` → `src/BrightnessTemperature.c`。
- **参数**：`HII_DIM`、`BOX_LEN`、`USE_TS_FLUCT`、`PHOTON_CONS_TYPE`；光锥侧还要求 `KEEP_3D_VELOCITIES`（RSD 需要水平速度）。

#### ⑥ Coeval 装配与收尾

- **作用与意义**：把这一轮的盒收进按量取用的容器，并清掉上一轮不再需要的中间量——红移循环的收尾动作。
- **对应阶段**：[S02.4 快照组装](../atlas/L2-subprocesses.md#s024-快照组装)（单元 [S02.4.1](../atlas/L3-units.md#s0241-generate_coeval)）
- **输入 / 产出**：输入 P06–P10；产出这一轮的 [P11 演化快照](../atlas/L0-pipeline.md#p11-演化快照) 形态（每红移一个 Coeval）。
- **关键位置**：`drivers/coeval.py` 的 `_redshift_loop_generator` 循环体末尾（装配 + 清理上一快照）。
- **参数**：`PHOTON_CONS_TYPE`（`z-photoncons` 时每轮刷新校准数据）、`MINIMIZE_MEMORY`（即时回收）、`HII_DIM`。

### ⑤ 输出层

#### Coeval 快照 / LightCone 光锥 / GlobalEvolution 全局历史

- **作用与意义**：三种收尾形态——按量取用的快照、沿视线切片拼起来的光锥、压成零维的红移历史曲线。
- **对应阶段**：[S02.4 快照组装](../atlas/L2-subprocesses.md#s024-快照组装)、[S02.5 光锥切片与拼接](../atlas/L2-subprocesses.md#s025-光锥切片与拼接)
- **输入 / 产出**：输入逐红移的亮温盒；产出 [P11](../atlas/L0-pipeline.md#p11-演化快照) / [P12](../atlas/L0-pipeline.md#p12-光锥) / [P13](../atlas/L0-pipeline.md#p13-全局演化历史)（三者都是手动 `save()`，不随缓存开关自动落盘）。
- **关键位置**：`drivers/coeval.py` 的 `Coeval`、`drivers/lightcone.py` 的 `LightCone`、`drivers/global_evolution.py` 的 `GlobalEvolution`。
- **参数**：`F_ESC10` / `F_STAR10` / `HII_EFF_FACTOR` / `POP2_ION`（E3 的单格参数派生）、`USE_TS_FLUCT`、`SOURCE_MODEL`。

#### OutputCache 落盘（按 CacheConfig 分类开关）

- **作用与意义**：把中间产物按类别写进缓存（也可只留最后一步），下次重跑靠它做断点续算。
- **对应阶段**：[S03 缓存与持久化](../atlas/L2-subprocesses.md#s03-缓存与持久化)（`S03.1` 缓存键与路径模板、`S03.4` 写盘策略开关）
- **输入 / 产出**：输入 P02–P10；产出缓存文件（不新增逻辑产物编号）。
- **关键位置**：`io/caching.py` 的 `OutputCache` / `RunCache` / `CacheConfig`。
- **参数 / 开关**：`CacheConfig` 八个字段（`initial_conditions` / `perturbed_field` / `spin_temp` / `ionized_box` / `brightness_temp` / `halobox` / `halo_catalog` / `xray_source_box`，默认全开）；清单内容随 `USE_TS_FLUCT` / `has_discrete_halos` / `lagrangian_source_grid` 变化。
- **分支**：见 [分支 H](#分支-h-断点续算与写盘开关)。

## 三 分支

**主图上凡是虚线边、或名称里带"仅 / 三选一 / 条件"字样的模块，都属于下面某个分支。**

### 分支 A 两条入口：命令行 run ics 与 Python API

- **触发条件**：`21cmfast run ics` 走左支（只算初始条件）；`21cmfast run coeval` / `run lightcone` 或 Python API 直接调三个驱动走右支。
- **分叉走向**：左支止于 [P02 初始条件](../atlas/L0-pipeline.md#p02-初始条件)；右支继续备料 → 逐红移循环 → 三种收尾。
- **位置**：`cli.py` 的 `run` 命令组（`ics` / `coeval` / `lightcone` / `params`）。
- **注意**：`run_global_evolution` **没有**命令行子命令，只有 Python API。

### 分支 B 三条时间流水线

- **触发条件**：入口 B 里选一条（不是并行跑三条）。
- **分叉走向**：
  - **E1 联合演化盒**：逐个红移交付完整盒（`yield` 过滤出目标红移），收尾形态是 P11 演化快照。
  - **E2 光锥**：多两步——每个红移后**切片**并沿视线拼接，最后做 RSD（需要 `KEEP_3D_VELOCITIES`）与 trimming，收尾形态是 P12 光锥。
  - **E3 全局演化**：先把参数派生成单格参数（`evolve_input_structs`），逐红移取盒均值，收尾形态是 P13 全局历史；**强制不落盘**（`CacheConfig.off()`）。
- **共用**：三者的"备料"与"逐红移循环"是同一份实现（`_setup_ics_and_pfs_for_scrolling`、`_redshift_loop_generator`）。
- **位置**：三条流水线的差异见 [L0 §1.3 三条时间流水线的伪代码对照](../atlas/L0-pipeline.md#13-三条时间流水线的伪代码对照)；逐行细节见 G2。

### 分支 C 源模型 SOURCE_MODEL

- **触发条件**：`SOURCE_MODEL` 取 `CONST-ION-EFF` / `E-INTEGRAL` / `L-INTEGRAL` / `DEXM-ESF` / `CHMF-SAMPLER` 五值之一（定义在 `wrapper/inputs.py`）。
- **分叉走向**（由它派生三个派生开关）：
  - `has_discrete_halos`（= 后两档）→ 才走 `evolve_halos` 与红移循环里的晕目录输入（[分支 F](#分支-f-离散晕-has_discrete_halos)）。
  - `lagrangian_source_grid`（= 后三档）→ 源项网格在拉格朗日型源下计算，缓存清单也多一类条目。
  - `mass_dependent_zeta`（= 第一档之后的档位）→ 电离判据里 ζ 随质量变化。
- **落点**：`src/HaloBox.c`、`src/IonisationBox.c`、`src/SpinTemperatureBox.c`、`src/HaloCatalog.c` 里按该值分支。
- **校验**：`SOURCE_MODEL` 与 `HMF` / `USE_INTERPOLATION_TABLES` 有交叉约束（`wrapper/inputs.py` 的 validator）。

### 分支 D 光子守恒 PHOTON_CONS_TYPE

- **触发条件**：`PHOTON_CONS_TYPE` 取 `no-photoncons` / `z-photoncons` / `alpha-photoncons` / `f-photoncons` 四值之一（定义在 `wrapper/inputs.py`）。
- **分叉走向**：
  - `no-photoncons`：`setup_photon_cons` 直接返回，整条校准链不启用。
  - `z-photoncons`：装配校准曲线，并且**每个红移**刷新校准数据；要求目标红移不低于 `PHOTONCONS_CALIBRATION_END`（默认 3.5），否则报错。
  - `alpha-photoncons` / `f-photoncons`：校准改作用在星族参数上（α 逃逸斜率 / 逃逸分数），不逐红移改红移。
- **落点**：`wrapper/photoncons.py` 的 `setup_photon_cons`；C 侧 `src/photoncons.c`、`src/IonisationBox.c`、`src/scaling_relations.c`。
- **`PHOTONCONS_CALIBRATION_END`**：校准曲线的红移下限；低于它继续要 z-photoncons 会直接报错。

### 分支 E 自旋温度涨落 USE_TS_FLUCT

- **触发条件**：`USE_TS_FLUCT` 为真 / 假（默认 False）。
- **分叉走向**：
  - 真：红移循环里多算 ② `compute_xray_source_field` 与 ③ `compute_spin_temperature`，缓存清单里多建 TsBox 条目。
  - 假：跳过这两步，电离步与亮温步用"自旋温度 = 背景温度"的占位（`TsBox.dummy()`）。
- **落点**：`drivers/coeval.py` 的红移循环；`io/caching.py` 的缓存清单。
- **注意**：`USE_MINI_HALOS` 要求 `USE_TS_FLUCT` 为真（validator）。

### 分支 F 离散晕 has_discrete_halos

- **触发条件**：`has_discrete_halos`（由 `SOURCE_MODEL` 派生，不由用户直接给）。
- **分叉走向**：
  - 真：备料阶段多一步 `evolve_halos`（逐红移晕目录）；红移循环每轮多装入一份晕目录；`compute_halo_grid` 必须有晕目录（否则退化为占位）。
  - 假：`evolve_halos` 直接返回空，源项网格只在网格上算。
- **落点**：`drivers/coeval.py` 的 `evolve_halos` 与循环体；`drivers/single_field.py` 的 `compute_halo_grid`。
- **注意**：多红移 + 离散晕时缓存会被关闭（避免读到不一致的中间态）。

### 分支 G 相对速度 vcb 与二阶扰动 2LPT

- **触发条件**：`USE_RELATIVE_VELOCITIES`（相对速度）与 `PERTURB_ALGORITHM == "2LPT"`（二阶扰动）。
- **分叉走向**：两者都在初始条件内部（见 [G3](G3-初始条件.md#三-分支)）：vcb 多出 `lowres_vcb` 并轻微改变 P(k)（只允许配 CLASS 功率谱）；2LPT 多算 φ₂ 并多产出 6 个数组。
- **落点**：`src/InitialConditions.c`；`src/PerturbedField.c` 在 `PERTURB_ALGORITHM > 0` 时做归一化。

### 分支 H 断点续算与写盘开关

- **触发条件**：缓存目录里已有满足条件的输出（`RunCache` 清单齐全），且没有要求 `regenerate`。
- **分叉走向**：命中则从"最后一个完整红移"的下一节点继续推进，并把已算的红移重建进容器；否则从第一个目标红移开始。
- **落点**：`_obtain_starting_point_for_scrolling`（判定）、`io/caching.py` 的 `RunCache` / `CacheConfig`（清单与开关）。
- **相关开关**：`CacheConfig` 八字段；`regenerate`；光锥侧还有自己的 checkpoint。
