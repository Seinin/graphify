> 这套文档（G1 主图 / G2 入口 B / G3 初始条件 / [G4 物理链](G4-物理链.md)）**画什么、怎么画**的唯一规约。
> 四份图文档开头只放一段摘要并链回本文；有冲突时以本文为准。
> 覆盖**两个页面**：G1–G3 讲画布页（`data/graph.json` 的父子图），G4 讲**物理链页**（`src/generated/physics-chain.json`，另一份数据、另一套一级）。两页只有规范共用，图与数据互不相干。
> 维护口径与 [atlas 维护契约](../atlas/CONVENTIONS.md) 一致：改标题 = 改锚点，跨层只链接不展开。

## 一 一句话规约

**一张图只画它这一层的事实。**

- 图上出现的每个节点、每条关系，都必须在**数据里有对应物**（节点 id / 边 id）；画布不许"补"出数据里没有的东西。
- 子图**只画本层**：父层关系**不**派生进子图（口径与原因见 §四）。

## 三 图的数据形态

### 3.1 节点分三类

| 种类 | 数据特征 | 画布行为 |
| :--- | :--- | :--- |
| **装饰容器**（层带 / S09 框 / E lane） | `type: group` | 子节点直接画在框里（compound 自动合围）；**不参与关系**（无连线手柄、拖线吸附跳过它）、**不可进入**、无悬停特效、不亮参数红点 |
| **模块**（类 / 函数，带子结构） | 非 `group` 且有子节点 | 名称后带 `· N` 徽标 + 呼吸光晕；双击 / 右键 / 属性页按钮进入它的子图 |
| **普通步骤** | 非 `group` 且无子节点 | 只能被选中、编辑、连线 |

节点类型另有要素配色：函数/过程（紫）、驱动/入口（蓝）、参数/变量（青）、数据/场（天蓝）、交付产物（品红）、容器/层带（墨绿）。

### 3.2 边的读法

- **产物不占节点**：产物名写在「生产步骤 → 消费步骤」这条边的 `label` 上（画布上悬停该线或用工具条「常显边标签」整读）。
- `conditional: true` = 这条流动**只在某些配置下成立**，画成虚线。
- 箭头形态固定为「两框中心连线、只露框外那一段」：`curve-style: straight` + 端点 `outside-to-node`。

### 3.3 参数标签（模块的"标签"）

- 图级注册表 `meta.tags` 登记参数（id / 名称 / 说明 / 分类 / 对应文档），节点用 `tags: [tag id]` 归属，`tagDetails` 写"这个参数在这个模块上具体怎么用"。
- 读法：顶栏勾选参数 → 命中模块**左上角亮红点** → 点红点 → 右侧属性面板展开该参数的明细（**参数名 · 用法（赋值 / 入公式 / 开关 / 校验）· 出处 `文件:行`**）。
- **点画布空白 = 回到什么都没点亮**：清掉选中（属性面板随之收起）**并**清空勾选（红点全灭）——与顶栏标签入口里的「清除」等价，仍是纯视图改动（不标脏、不落盘）。展开着的图例也在这一下同时收起（同一个手势不拆成两下）。右键点空白只弹画布菜单、不改选中；已经在看的子图标签页也不会被这一下关掉。
- **每个标签都必须有一篇 notes 文档**（服务端 schema 强制），所以"新增参数标签"= 同时新增一篇参数文档。

### 3.4 引用（节点上的"出处"）

节点 `refs` 同时支持两类目标：notes 文档（`docId` + `anchor`）与源码（`file` + `line`/`endLine`）。**anchor 就是标题的 slug**（见 §六）。

### 3.5 物理链页的要素（G4 那一页）

第二页用的是另一份数据（`src/generated/physics-chain.json`），节点分四类：

| 种类 | 数据特征 | 画布行为 |
| :--- | :--- | :--- |
| **过程块** | `kind: "process"` + `enterable: true` | 一级节点；可双击 / 右键 / 属性页进入子图，带呼吸光晕 |
| **层** | `kind: "layer"` + `enterable: false` | 一级节点（常数与网格）；成员是常数、互不相干（无块内边），不给进入口 |
| **块内成员** | 出现在某块的 `members` 里 | 只在**该块的子图**里出现；`engineering` 类型的成员呈暗色 |
| **接口边 / 回流边** | 边 id 形如 `iface:block:A->block:B` / `feedback:block:A->block:B` | **静息不画**：悬浮块时显现，指针离开隐去；标签写跨块流动的量。**属性页不列它**（跨块送了什么在画布上悬浮块时就看得见，右侧栏再铺一张进出清单是重复） |

- 参数与标签、引用（`refs`）的读法与画布页相同（§3.3 / §3.4）；物理链页的参数以**左栏「检索与词条」**（按生成物里的代码类名分组 + 四路检索）为主入口，标签注册表为辅。这一栏与画布页「notes 数据库」同一套面板机制：可拖宽、可收成细条、宽度本地记忆。物理链页的**块**（`type = process`）是成员的父节点，但它是天体物理过程本身（不是装饰），所以选中参数时**块也亮红点**——装饰容器不亮红点的判据是 `type = group`。
- `Snn` 在物理链页**不是一级骨架**：它是量的属性（`node.stage`），块上只暴露成员的并集（`blocks.items[].stages`）；**属性页不显示它**（点不开的摘要，回答不了"这段代码在哪"），按 `S14` 检索仍是命中面，落点由「源码」标签页的文件 + 行区间回答。

## 四 子图与父图的关系（不继承父层关系）

- **子图只画它自己这一层的事实**：子图里出现的节点与边，全部是图数据里真实存在的条目；**不派生**任何"父层邻居卡"或"父层关系线"。
- 要看某个模块与外部的关系，回**主图**看（模块级的边都在那里），或在**属性面板**的关系列表里看；子图不重复表达父层的内容。
- **为什么不做继承**（曾经做过，已废弃，不要再加回来）：把父层关系派生进子图，会让同一个函数在子图里外各出现一次。`_setup_ics_and_pfs_for_scrolling` 就是活例——它在数据里有 4 个节点（② 编排层的模块节点 + E1/E2/E3 三条 lane 里的「② 备料」步骤），进入 `入口 B` 子图后，里面三个步骤与外面派生出的「↗」卡片同时可见，自相矛盾。
- 因此子图里**不会**出现：带 `↗` 前缀的卡片、虚线派生线、以及任何数据里查不到的节点 id / 边 id（也没有"内部落点"这类需要额外字段的概念）。

| 想知道什么 | 去哪看 |
| :--- | :--- |
| 一个模块与外部的关系（谁调用它、它又调用谁） | 主图（模块级的边），或属性面板的关系列表 |
| 一个模块内部有哪些步骤、步骤之间怎么接 | 该模块的子图（[G2 入口 B](G2-入口B.md) / [G3 初始条件](G3-初始条件.md)） |

## 五 画布视觉与交互约定

| 事项 | 约定 |
| :--- | :--- |
| 虚线 | **只有一个含义**：条件 / 可选（节点虚线框 = 这一步只在某些配置下存在；边虚线 = 这条流动只在某些配置下成立） |
| 提供 / 数据流动（物理链页） | **实线 + 弧线 + 紫灰**：弧线表达"这条箭头跳过了几层"，线型不参与表达——这一档讲的是跳层、不是"有时才有"，所以不占用虚线这一档；跨轮的那一档另用长划与品红（见 G4 §2.2） |
| 大框（容器） | 实线；悬停不变色、不放大；选中只加粗描边 |
| 悬浮模块 | 按自身基准放大约 1.32 倍、描边加深、显示与它相邻的关系名，其余元素（连文字）虚化 |
| 缩放过小 | 藏掉非容器标签，只留大框标题作为骨架 |
| 参数红点 | 画在模块左上角，是真实按钮（点它 = 选中该模块 + 展开参数明细） |
| 层级移动 | 把节点拖进大框范围即建立父子层级；大框随子节点自动合围 |
| 布局 | 默认**手动摆放**、坐标自动保存；每个标签页有自己的布局方式与视口 |
| 接口边（物理链页） | **静息不画**，悬浮块时显现、指针离开隐去（口径见 §3.5）——"一级不要一堆乱箭头"就是靠这条达成的；**属性页不铺进出清单** |
| 块的进入权 | 由数据的 `enterable` 决定（过程块可进入、层不可进入），视图不临时判断；自检另有一条断言守「`enterable` 与块内连通性一致」 |
| 图例 | 贴画布**左下角**、默认收起成一枚「图例」按钮，点开在它**上方**铺出浮层（往下是画布下边界）。**两段条目都按"此刻真画出来的"派生，不是写死的清单**：要素种类由渲染器按此刻**可见的节点**报出（收起来的话题、别的标签页、收起的分支都不占条目），线型按此刻**可见的边**报出——藏起来的跨红移回流不占条目，关掉开关那一条就跟着消失。条目里的色值与线型取自样式表同用的常量，样例线段按同一档画（含弧线那两档） |

### 6.2 编号与标题

- 编号沿用**图内圈码**（`① 入口层`、`① 红移表 …`）与 **atlas 的 `Snn` / `Snn.m`**（阶段 / 子过程）。本套文档**不新增编号体系**，实现细节一律链接 `../atlas/L0-pipeline.md`、`L1-stages.md`、`L2-subprocesses.md`、`L3-units.md`、`L4-key-processes.md`。
- 标题写成 `### <编号> <名称>`，编号与名称之间只有一个半角空格，名称尽量不出现标点。
- **锚点 = GitHub slug**：先转小写，再删掉所有「非字母 / 非数字 / 非空格 / 非 `-` / 非 `_`」的字符（`·`、`/`、`（）`、`→`、`×` 都会被删掉），最后把连续空白转成一个 `-`。同文档内重名标题会依次得到 `-1`、`-2` 后缀。
- 例：`### 入口 · 命令行 / Python API` → `#入口-命令行-python-api`；`### ① 红移表 _get_required_redshifts_coeval` → `#①-红移表-_get_required_redshifts_coeval`。
- 文档里的代码位置写「**文件 + 符号名**」（行号只作辅助，会漂移）；源码链接相对本目录上溯三层，形如 `../../../src/py21cmfast/drivers/coeval.py`。

## 七 自检清单

1. 图上的**每个节点**都能在本套文档里找到小节（见各文档「节点与锚点对照」表）。
2. 每个跨层链接的目标锚点在目标文件里确实存在；没有悬空引用。
3. 每个参数要么在注册表里（给 `tag id` + 分类 + 参数文档路径），要么明确标成「待注册」。
4. 子图里没有任何派生元素：没有 `↗` 卡片、没有数据里查不到的节点 / 边 id。
5. 分支都写清了**触发条件**与**分叉走向**；产物都写清了载体与是否落盘。
6. **物理链页**（G4）：每个一级块都在 §2.1.1 有小节（含那 1 个不可进入的层）；文中引用的成员数 / 边数 / 参数分组数与生成物一致——`cd Graphify && npm run check:chain` 可核对（当前 268 项断言全过，含「块属性页不列对外接口」这条反面断言）。
